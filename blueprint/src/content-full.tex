\chapter{The ABA case study}


This section is a case study: the verification of an implementation of Asynchronous Byzantine Agreement against a small specification, by probabilistic forward simulation, built on the five results proved above.
The setting is $n$ processes, each holding an input bit, of which at most $f$ are Byzantine, with $3f < n$, communicating by asynchronous message passing.
The development lives in the opt-in \texttt{Leslie2Protocols} Lake library.


\section{Setting and method}


Three protocols occur in the case study.
Each is given as a list of properties over the calls and returns of its interface.
A property speaks only of \emph{correct} processes, that is, of processes that are never corrupted.

Asynchronous Byzantine Agreement (ABA).
Processes start with a bit in $\{0,1\}$ and may return a bit.
\begin{itemize}
  \item Validity: if a correct process returns $b$ then a correct process had
    $b$ as input.
  \item Agreement: if two correct processes return, then their outputs are
    equal.
  \item $\varepsilon$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\varepsilon$, all correct processes will eventually return.
\end{itemize}

Graded Binding Crusader Agreement (GBCA).
Processes start with a binary input in $\{0,1\}$ and may return a value in
\[
  \{(0,A),\ (0,B),\ (\bot,C),\ (1,B),\ (1,A)\}.
\]
\begin{itemize}
  \item Validity: if a correct process does not return $(b,A)$ then a correct
    process had $1-b$ as input.
  \item Graded Agreement: if two correct processes return $(b,X)$ and
    $(b',X')$ then $b = 0 \Rightarrow b' \neq 1$ and $X = A \Rightarrow X' \neq \bot$.
  \item Binding: when a correct process returns then a bound value $b$ is
    defined and, in all extensions of the execution, correct processes do not return $(1-b,B)$ or $(1-b,A)$.
  \item Termination: if $n-f$ correct processes take part in the protocol then
    all correct processes will eventually return.
\end{itemize}
In the second clause of Graded Agreement the symbol $\bot$ stands in the grade component, where the return domain admits only $A$, $B$ and $C$. It is read here as the grade $C$, the sole grade paired with the value $\bot$.
The encoding realises that reading: an $A$-return and a $C$-return of the same instance exclude one another.
The bound value of the Binding clause is realised by its complement: the specification carries the set of bits it can no longer hand out, and the clause's $1-b$ is a member of that set (D19).

Weak Common Coin (WCC).
Processes start with no input and may return a bit.
\begin{itemize}
  \item $\varepsilon$-Goodness: with probability $\varepsilon$, all correct
    processes return $0$ (resp.\ $1$).
  \item Unpredictability: until $f+1$ processes have called WCC, all outcomes
    are still possible.
  \item $(1-\failmass)$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\failmass$, all correct processes will eventually return.
\end{itemize}

What this development establishes is Validity and Agreement for ABA, machine-checked.
What it does not establish is the rest.
Termination, Unpredictability and fairness are out of scope.
The weak common coin is held at specification level rather than implemented: its own implementation over Gather and SRSD is not modelled here, so $\varepsilon$-Goodness enters as an assumption.

Every protocol $P$ with sub-protocols $Q$ is treated in two moves.
The first move is substitution: in a fixed context, each sub-implementation is replaced by the corresponding specification, which is sound by precongruence.
The second move is the core simulation: the core algorithm of $P$ composed with the specifications of its sub-protocols is simulated by the specification of $P$. Composing the inclusions places the implementation of $P$ inside the specification of $P$. The recursion stops at WCC, which is left at specification level.
GBCA is carried to implementation level twice, by two verified implementations of one specification.
The direct implementation calls no sub-protocol, so no further substitution arises there.
The gather-based implementation of Section~\ref{sec:aba-gather} continues the recursion: GBCA over two gather instances, gather over reliable broadcast, and reliable broadcast concrete.
The subject of the argument is the protocol: $n$ programs beside a network adversary and a coin oracle, given in that form in Section~\ref{sec:aba-protocol-reading} --- one automaton per process, carrying that process's round loop beside its stage-side record and a flag saying whether its own program has been replaced, and one automaton holding the message sets, the corrupted set and the corruption budget.
Substitution needs the sub-protocol it replaces to be a component, so the first step of the argument reads that system as a composition of components (Theorem~\ref{thm:aba-protocol-composed}).
That step is an inclusion, and it is where the chain passes from implementation to specification: the composed reading carries the message state of every round, which no process holds, and a round instance answers at a process the protocol has terminated (D22).
The substitution then runs in those coordinates, and the hand-built core simulation runs in them too.

\paragraph{Object names.}
Transition System~1 is the ABA specification, Transition System~2 the GBCA specification, Transition System~3 the WCC specification, Transition System~4 the gather specification and Transition System~6 the BRB specification.
These names are used throughout this section and follow the numbering of the source blueprint~\cite{LeslieBP}, whose Transition Systems~5 and~7 (SRSD and AVSS) are not encoded; the source's pseudocode is numbered there as well: the source blueprint's Algorithm~1 is the ABA core algorithm, its Algorithm~2 the GBCA implementation, its Algorithm~4 the gather implementation over reliable broadcast (taken from~\cite{AFW25}) and its Algorithm~6 Bracha's reliable broadcast (taken from~\cite{Bra87}).
Of its Algorithms~1 and~2 only the ABA core is reproduced here; Algorithms~4 and~6 are both encoded, in Section~\ref{sec:aba-gather}.
The cited paper carries a third, independent numbering, always written here with ``ABDY22's'' attached: ABDY22's Algorithm~2 is the weak-coin agreement framework $AA_\varepsilon$, which the source blueprint's Algorithm~1 realises (ABDY22's Algorithm~1, the strong-coin framework over ungraded BCA, is not encoded in this development); ABDY22's Algorithm~6 is the graded sub-protocol.
The GBCA implementation this chapter displays and encodes is ABDY22's Algorithm~6, of which the source blueprint's Algorithm~2 is a compression that violates Binding (D18).
A cross-reference of the form ``Algorithm~\ref{alg:aba-core}'' always points to a displayed float of this document, whose numbering runs independently of both; the other two numberings appear only in the phrases ``the source blueprint's Algorithm~$k$'' and ``ABDY22's Algorithm~$k$''.
Bracha's third message level is $\mathrm{VOTE}$ here and in the source blueprint, where both~\cite{ABDY22} and~\cite{AFW25} write $\mathrm{READY}$.
Its echo threshold is $n-f$ here and in the source blueprint, where~\cite{AFW25} writes $(n+f)/2$.
Its return quorum is $n-f$ where~\cite{AFW25} writes $2f+1$, the two coinciding at $n = 3f+1$.
The encoding follows the source blueprint at each point, so none of the three carries a deviation label.


\paragraph{Outside the model.}
Two features of~\cite{LeslieBP} are deliberately not encoded.
The first is fairness: the source marks each transition fair or unfair, and a fair execution is one that is finite and ends in a fair deadlock or contains infinitely many fair transitions.
The second is partial information: the source carries adversaries given by a pair of observation functions on states and on labels, together with the belief construction that turns such an adversary into an omniscient one on a derived system.
Neither appears here.
Every adversary in this section is omniscient, so the observation functions are the identity and the belief construction is not needed.
The fairness markings bear only on liveness, which is out of scope.

\paragraph{Notation.}
Write $[n]$ for the identifier set and $F \subseteq [n]$ for the corrupted set.
The value domain of Transition System~3 is $\{0,1,\bot,\top,\dagger\}$, the type
\leandecl{PLTS.ABA.TVal}, where $\bot$ is unresolved, $\top$ is an adversarially
resolved outcome, and $\dagger$ is a resolution that delivers to no process (D17).

Every transition rule is displayed as a guard above a labelled step into an explicit distribution.
A Dirac target and a genuinely probabilistic one are therefore distinguishable in that display.
Exactly two transitions in the whole development are non-Dirac: the flip of Transition System~1 and the coin resolution of Transition System~3.
Both follow the same distribution, displayed in Definition~\ref{def:aba-params}; the flip reads it through the map that drops the bit (D21).


\section{Deviations from the source blueprint}
\label{sec:aba-deviations}

The encodings depart from~\cite{LeslieBP} in catalogued ways.
Each departure carries a label and is cited at the point where it applies.
The labels D2, D3, D6, D7 and D20 are not in use.
\begin{itemize}
  \item D1: corruption is a guarded deterministic transform, broadcast to every
    component.
    The label $\mathrm{fail}(id)$ fires only under $id \notin F \wedge |F| < f$, so a corruption fires exactly where it takes effect.
    The guard sits on the row of the component that owns the corrupted set: rule~6 of Transition System~1, and the network adversary in the implementations.
    The sub-protocol specifications take the label totally, their own copies of $F$ kept in lockstep by the broadcast.
    The transform is $\mathrm{corrupt}$, which inserts $id$ into $F$ and writes nothing else.
    The half of the broadcast taken at the process the label names replaces that process's program, the replacement itself being D23.
  \item D4: the WCC \texttt{guess} label and the \texttt{guess} state field are
    omitted.
  \item D5: a set-based authenticated network with per-sender message sets.
  \item D8: protocol sends guarded by prior participation.
  \item D9: $0$-based round indexing.
  \item D10: the per-round bookkeeping between the coin return and the next
    call fused into the $retW$ step, which multicasts DECIDED on an $A$ grade.
  \item D11: Byzantine call and return rules at each handshake.
    A replaced program's sub-protocol messages is the handshake rows' business; its interface messages is D23's.
  \item D12$'$: per-process DECIDED sent and received sent sets, delivery per
    (receiver, sender, bit), and Byzantine equivocation in those sent sets.
  \item D13: the Validity provenance apparatus on Transition System~1, namely a
    ghost record $input$ of the genuine $\mathrm{callABA}$ events and an $f+1$ support guard on the decision, rule~4.
    The record has two writers, the interface rules~1 and~2: rule~1 overwrites while nothing is decided, and rule~2, the unguarded loop that makes $\mathrm{callABA}$ input-enabled, records first-write-wins.
    Neither write is a claim about who called honestly.
    The support guard on rule~4 is what turns the record into provenance.
  \item D14: $f+1$ support guards on the GBCA specification's binding, on the
    dissenting bit at its $B$-return, and on each of the two bits at its $C$-return.
  \item D15: the $F$-blind form of those support counts, namely $f+1$ distinct
    callers-or-corrupted.
  \item D16: the two-phase abstract state used by the core simulation, which
    defers the specification's $\tau$-progress to a single $decide$ step under the first visible return.
    The overwrite performed by rule~1 of Transition System~1 is what makes the deferral sound: a bit written to the record by the unguarded loop rule stays revisable until a value is decided.
  \item D17: a fourth outcome $\dagger$, of mass $\failmass$, on the single
    distribution both coin resolutions follow, rule~3 of Transition System~1 and rule~3 of Transition System~3.
    It carries the delivery failure of the $\varepsilon$-correct secret-sharing coin implementation that the source builds on, where both of the source's resolutions range over $\{0,1,\top\}$ only.
    A $\dagger$ round of Transition System~3 enables no return.
    At Transition System~1 the outcome of mass $\failmass$ is the undelivered branch of the flip, which puts the system into the mode $terminal$.
    The mode $terminal$ enables no $\tau$-rule.
  \item D18: the GBCA implementation transcribes ABDY22's Algorithm~6 in full
    --- six rounds, the message levels INPUT, ECHO, VOTE, BIND and ECHO5, and the decide conditions of that algorithm --- in place of the source blueprint's Algorithm~2, which is a four-round compression of it.
    The compression elides the ECHO5 level, reads the three decide conditions one message level down, and takes $f{+}1$ $\mathrm{VOTE}\,v$ receipts as the grade-$1$ witness where Algorithm~6 takes $f{+}1$ $\mathrm{BIND}\,v$ receipts.
    The first four levels carry the source blueprint's names; the fifth is $\mathrm{ECHO5}$ after \cite{ABDY22}, which is the only source that has it.
    That compression violates Binding.
    One process held at the echo stage through a $C$-return may afterwards direct its write-once echo at either bit, and a single corruption completes the $f{+}1$ $\mathrm{VOTE}\,v$ count for the bit the adversary picks, so two extensions of one $C$-return hand out two different bits and no binding-faithful specification simulates the compression.
    The source blueprint carries a matching red annotation at those decide conditions.
  \item D19: the GBCA specification state carries an exclusion set
    $excluded \subseteq \{0,1\}$, the bits the instance can no longer hand out, in place of the source's bound value $bind \in \{0,1,\bot\}$.
    The set is the excluded-bit reading of that value.
    Its only writer is the internal binding transition, which fires from $excluded = \emptyset$ alone, so every reachable state has $excluded = \emptyset$ or $excluded = \{b\}$ for one bit $b$, and the bound value embeds onto exactly those states, $bind = \bot$ as $excluded = \emptyset$ and $bind = b$ as $excluded = \{1-b\}$.
    The two state shapes therefore differ in the guards rather than in the cardinality.
    The source's guard $bind = v$ on the value-bearing returns becomes the pair $v \notin excluded$, $1-v \in excluded$; its guard $bind = \bot$ on binding becomes $excluded = \emptyset$; and the $C$-return's binding obligation $bind \neq \bot$, which in the source also puts the bound value on the return label, becomes $|excluded| \ge 1$, read off a label that names no bit.
    Binding is thereby negative and monotone --- the internal transition adds one bit and no rule removes one --- which makes Graded Agreement and Binding structural rather than invariants of the specification (Theorem~\ref{thm:gbca-spec-binding}) and carries the safety half of Validity (Theorem~\ref{thm:gbca-spec-validity}).
  \item D21: Transition System~1 is eight rules over the record
    $\{input, ret, F, val, mode\}$, in place of the source's per-process call row and five-valued coin.
    The coin is an abstract flip, rule~3, which resolves once per firing into a lock, a release or a failure to deliver and names no bit; the mode $mode \in \{idle, locked, terminal\}$ it writes is the whole of the round structure the source spreads over a call row, a bound value and a coin field.
    The flip carries the mixedness guard beside $mode = idle$ and $val = \bot$: it fires only from a state where each of the two bits carries $f+1$ support.
    The decision is a single guarded write, rule~4, of a bit carrying $f+1$ $F$-blind support.
  \item D22: retention with termination.
    A process record is the pair $\mathrm{ProcRec}(n) = \mathrm{CoreRec}(n) \times \mathrm{StageSideRec}(n)$, and the stage-side record holds a finite map $stages$ from rounds to graded-agreement stage records together with a flag $terminated$.
    The stage record of round $r$ is read $\mathrm{stage}\,r$: the retained record where the process has touched round $r$, the initial stage record elsewhere.
    The map is finite by its type, so a process holds finitely many stage records at every point of a run, and the round advance resets none of them.
    Every stage-side rule is accordingly round-indexed rather than round-guarded: it reads and writes the stage record of the round its own label tags, whichever round the round loop is in, and its guards are the guards of that stage record together with $terminated = \mathrm{false}$.
    A process therefore answers the messages of a round its round loop has passed, and a delivery of any round is filed.
    That is the amplification response of the cited paper~\cite{ABDY22}, whose liveness argument counts the messages a process sends after its own decision (its Lemmas~4.6 and~E.5), and those lemmas are stated under the hypothesis that no non-faulty process has terminated.
    Termination is a $\tau$-rule of its own, $terminate$, which fires once the process's own return has fired and $2f+1$ DECIDED receipts are on its record, and whose effect is to set $terminated$ and nothing else.
    The retained stage records are frozen from that point.
    The cited paper separates deciding from terminating, a process deciding and then eventually terminating (its Definitions~3.1 and~3.2), and the threshold $2f+1$ is the point of its note on termination: every process still running will cross the relay threshold of D12$'$ without a further stage-side response from this one.
    The DECIDED rules carry no termination guard, so a process that has terminated keeps relaying the payloads it holds.
    That committed broadcast is what makes the threshold sound.
    The Byzantine stage rows keep their labels and their network rows but have no row at the process they name, and a corrupted process's stage messages enter through the network's own $\mathrm{byzG}$ injection.
    The rule $terminate$ carries the replacement guard of D23, so a process whose program has been replaced never terminates.
  \item D23: when a process is corrupted its program is replaced.
    The round-loop record carries the flag \leandecl{PLTS.ABA.CoreRec.corrupted}, and the process's own half of the corruption broadcast,
    \leandeclnamed{failSelf}{PLTS.ABA.Net.FlatProcStep.failSelf}, is the row
    that writes it.
    Every honest row of the program is enabled only at an unreplaced program, so the record beneath the flag stands still from the corruption on: the phase, the estimate, the round, the receipt rows and the retained stage records all freeze where they stand.
    In place of those rows the replaced program is the single self-loop
    \leandeclnamed{corruptedIdle}{PLTS.ABA.Net.FlatProcStep.corruptedIdle},
    taken on every label other than $\tau$ and the labels on which the process would act on its own sub-protocol messages.
    On the latter the replaced program has no row at all, so under full synchronisation those labels cannot fire.
    What the corrupted process does on its sub-protocol interfaces runs instead through the handshake rows of D11, what it multicasts through the injections $\mathrm{byzG}$ and $\mathrm{byzD}$, and neither has a row at the process it names; a delivery addressed to a corrupted process fires nowhere.
    The visible interface is the exception.
    Both networks carry a Byzantine return row, $\mathrm{retABA}(id,b)$ at a corrupted process for either bit under the authorisation $id \in F$ alone and with none of the DECIDED evidence the honest row demands, and the replaced program's self-loop is the other half of it.
    At Transition System~1 the image of the replacement is the pair of corrupted interface rules, rules~7 and~8.
    Rule~7 records a bit unrelated to the one its label declares; rule~8 returns any bit at any time without moving the state.
    The honest rules stay available to a corrupted process, so the two rules add behaviour and remove none.
    The trace predicates accordingly quantify over never-corrupted returners, which is the quantification of the papers' own contracts.
  \item D24: the gather-based GBCA implementation follows Algorithm~4
    of~\cite{AFW25} at $R = 2$, the branch of lines~4 to~8 that calls the gather subroutine twice.
    Line~3 decides after the first gather when $R = 1$, and three grades fix $R$ at $2$.
    The grade is read off the second gather's counts in place of lines~7 and~8, which set it by an approximate-agreement subroutine on an input of $R$ or $0$, given concretely in \cite{AFW25}'s Appendix~B.
    A process reaches the top grade there only when enough others also chose $R$, and here on its own count alone: $(v, A)$ at $|{\rm dom}\, h| - f$ entries of $v$, $(v, B)$ at $f{+}1$, and $(\bot, C)$ below both.
    Line~5 takes the returned bit from the $f{+}1$ test and line~6 the grade from the $|{\rm dom}\, h| - f$ test, and grade $A$ ties both to the latter.
    That is sound because $|{\rm dom}\, h| - f \ge n - 2f \ge f + 1$ carries the heavy bit past the $f{+}1$ bar, where \cite{AFW25}'s Lemma~18 makes it unique.
    The source blueprint supplies no gather-based GBCA; its gather serves the coin construction through SRSD, which stays at specification level here.
    \cite{AFW25} is therefore the algorithm's source of record, and Transition System~2 is unchanged as its specification: the two implementations of graded agreement share the round interface, the specification and every statement downstream of it.
  \item D25: the gather specification holds its binding content as a
    write-once \emph{core family} in the state --- a nonempty set of committed-entry sets, any two of which (each with itself) share at least $n - f$ entries, every return dominating some member --- in place of Transition System~4's single bound identifier set, written once by an internal rule and carried on every return label.
    Two differences, one of form and one of substance.
    Form: the binding object moves from the return labels into the state, the returns carrying the output alone, since the only consumer of the instance is the round built over it.
    Substance: the single set of the classical statement is the family's intersection, and its $n - f$ size bound is a fact about complete executions rather than a predicate of reachable states --- at $n = 3f + 1$ a state at the first return has as few as $n - 2f$ honest votes cast, and fixes no single $n{-}f$-sized set every future return must dominate (\cite{AFW25}, Remark~22, reads the core of a gather without binding as determined only in hindsight).
    The family of committed $\mathrm{BIND}$ payloads is what such a state does determine, and the pairwise bound is what every counting argument of the two-gather round is re-derived from.
    On the implementation side the $\mathrm{BIND}$ payload is sent by reliable broadcast rather than on the message state --- ``committed'' must survive the sender's later corruption, and a broadcast value is write-once whatever happens to its sender.
  \item D26: the gather specification records the environment's calls and the
    committed entries in separate fields, a per-entry internal commit writing $val(k)$ once under the guard $k \in F \vee call(k) = v$, in place of Transition System~4's rule writing $call$ itself at a corrupted process.
    The split is what a process corrupted after its call requires: until its entry commits, such a process may still direct the committed payload, and the guard reads $F$ at the commit rather than at the call.
  \item D27: the BRB specification splits the leader's recorded input from the
    committed value, an internal commit writing the value once under $\mathit{ldr} \in F \vee input = m$, in place of Transition System~6's single call field and its corrupted-leader rule, which can only bar the instance from returning.
    Under Transition System~6 an honest call pins every return to the called value, and a leader corrupted after that call but before any correct process holds an echo quorum can make Bracha's rounds deliver a different value, which no resolution of that system's nondeterminism returns; the commit guard restores the leader's power to the window the implementation actually leaves open.
    Totality, a liveness property, is not encoded (Transition System~6, whose stated scope is the linear properties, does not encode it either; the fairness markings that carried it are outside the model).
  \item D28: composite instances are single rule tables over joint states
    rather than synchronised compositions with a hidden API, the shape the source's Definitions~19 and~20 use for gather over BRB.
    A sub-protocol's call and return are fused into the rows of the caller --- the gather call contributes to the input broadcast in the same step, the $\mathrm{BIND}$ send is the bind-broadcast call, and the first gather's return to a process is that process's call of the second gather --- and a sub-instance's delivery is a derived predicate on its state coordinate, read by the consuming row, not an event of the composite.
    The interface the protocol shares is unchanged: the fused readings speak the round alphabet, and the substitutions inside the round replace one layer of coordinates at a time.
\end{itemize}

\subsection{The ABA specification and its safety}

The three specification systems locate the adversary differently from the implementations they stand for.
An implementation pairs processes that read only their own replacement flag with an explicit network-adversary PLTS, which owns the corrupted set together with its budget and authorises every Byzantine action by the guard $k \in F$ of a component.
A specification carries no network component at all.
Its adversarial transitions are bare nondeterministic choices, resolved by the scheduler: the corruption rule of Transition System~1, its two corrupted interface rules (D23), the adversary-chosen returns under $\top$ at Transition System~3, and the disjunct $id \in F$ in the $F$-blind support counts of Transition Systems~1 and~2.
Leaving those choices unstructured is sound, because a specification constrains from above.
An unstructured adversary makes the specification more permissive, never less.
Trace-distribution inclusion asks that every behaviour of the implementation be matched by some resolution of the specification's nondeterminism, and the safety theorems quantify over all such resolutions.
A specification adversary with more freedom therefore weakens neither obligation.

\input{nodes/def-aba-spec}

The specification has four control states, keyed on the mode and on whether a value is decided: \emph{idle} ($mode = idle$, $val = \bot$), \emph{locked} ($mode = locked$), \emph{terminal} ($mode = terminal$) and \emph{decided} ($val \neq \bot$).
Rule 3 (\leandeclnamed{coinFlip}{PLTS.ABA.SpecStep.coinFlip}) is the branch out of \emph{idle}, and it is the only probabilistic transition of the system.
Its three outcomes carry $\varepsilon$, $1-\varepsilon-\failmass$ and $\failmass$: the flip locks, leaves the state unchanged, or fails to deliver (D17).
Rule 4 (\leandeclnamed{decide}{PLTS.ABA.SpecStep.decide}) is the sole writer of $val$, and it is the only $\tau$-rule that \emph{locked} can enable.
Enabledness is wider than the control graph shows.
Rule 2 fires in every state and rule 1 wherever $val = \bot$; rule 6 fires wherever the identifier it names is uncorrupted and the budget has room, and rules 7 and 8 wherever the identifier it names is corrupted.
Rule 3 asks the mixedness guard beside $mode = idle$ and $val = \bot$: both bits must carry $f{+}1$ support, so a run on which one bit is never supported never flips.
Rule 4 is enabled at every state with $val = \bot$, $mode \neq terminal$ and some bit carrying $f{+}1$ support, hence at \emph{idle} as well as at \emph{locked}.
At \emph{decided} the enabled rules are 2, 5, 6, 7 and 8, and at \emph{terminal} they are 1, 2, 6, 7 and 8; neither state enables a $\tau$-rule.
The guards on rule 4 are the entire constraint on the value decided (D13).

A locked flip cannot be discarded: at $locked$ the decision is the only $\tau$-rule the mode can enable.
The undelivered branch of mass $\failmass$ (D17) is absorbing: $terminal$ enables no $\tau$-rule.
The flip carries the mixedness guard, so the branch is reachable only from a state where both bits carry $f{+}1$ support.

\noindent\textbf{Transition System 1: the ABA specification.}

\medskip \noindent\textbf{State.} The record \leandecl{PLTS.ABA.SpecState}.
\begin{itemize}
  \item $input : [n] \to \{0,1,\bot\}$, a ghost record of the genuine $\mathrm{callABA}$ events (D13).
  \item $ret : [n] \to \mathbb{B}$, which processes have returned.
  \item $F \subseteq [n]$, the corrupted set.
  \item $val : \{0,1,\bot\}$, the decision value; once it is a bit, every return carries it.
  \item $mode \in \{idle, locked, terminal\}$, the control mode, \leandecl{PLTS.ABA.Mode} (D21).
\end{itemize}
\noindent Here $\mathbb{B}$ is the two-element type, written $0,1$ for protocol bits and $\mathrm{false},\mathrm{true}$ for flags.
The record carries no per-process call row, no bound value and no coin field: the mode is what the three of them are replaced by (D21).
The source blueprint's $Initial$ clause mentions an undeclared $out$ field; the field is omitted.

\noindent\textbf{Labels.} $\mathrm{callABA}(id,b)$, $\mathrm{retABA}(id,b)$, $\mathrm{fail}(id)$ and $\tau$, for $id \in [n]$ and $b \in \mathbb{B}$.

\noindent\textbf{Input-enabled labels.} $\mathrm{callABA}(id,b)$, by the unconditional loop rule~2.
The label $\mathrm{fail}(id)$ is enabled where $id \notin F$ and $|F| < f$, the guards of rule~6 (D1).

\noindent\textbf{Initial.} $input = \bot^{[n]}$, $ret = \mathrm{false}^{[n]}$, $F = \emptyset$, $val = \bot$ and $mode = idle$, the superscript marking a constant map on $[n]$.

\medskip \noindent In each rule $id \in [n]$ and $b \in \mathbb{B}$ are parameters, and $s$ is the source state.
Write $SuppOK(s,b)$ for
\[ \bigl|\{ id \in [n] : input[id] = b \ \vee\ id \in F \}\bigr| \ \geq\ f + 1 , \]
the $f{+}1$ $F$-blind support of $b$ (D13, D15), \leandecl{PLTS.ABA.SuppOK}.

\medskip
\noindent\textbf{1.} \leandeclnamed{callSet}{PLTS.ABA.SpecStep.callSet} (D13, D16).
Guard $val = \bot$.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;}
   \delta\bigl(s[\,input[id] := b\,]\bigr) \]
The write is an overwrite: while nothing is decided the record is revisable, so it holds the bit of the last such call.

\noindent\textbf{2.} \leandeclnamed{callLoop}{PLTS.ABA.SpecStep.callLoop} (D13).
No guard.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;}
   \begin{cases}
     \delta\bigl(s[\,input[id] := b\,]\bigr) & \text{if } input[id] = \bot,\\
     \delta(s) & \text{otherwise.}
   \end{cases} \]

\noindent\textbf{3.} \leandeclnamed{coinFlip}{PLTS.ABA.SpecStep.coinFlip} (D17, D21).
Guard $mode = idle$, $val = \bot$ and $SuppOK(s,b)$ for each of the two bits $b$, the mixedness guard.
\[ \begin{aligned}
     s \xrightarrow{\;\tau\;}\ \
     &\varepsilon\cdot\delta\bigl(s[\,mode := locked\,]\bigr)
     + (1-\varepsilon-\failmass)\cdot\delta(s)\\
     &{}+ \failmass\cdot\delta\bigl(s[\,mode := terminal\,]\bigr)
   \end{aligned} \]
The three masses are the image of the coin distribution of Definition~\ref{def:aba-params} under the map that drops the bit, \leandecl{PLTS.ABA.flipPMF}: one bit goes to the lock, the other bit and the adversarial outcome to the release, and $\dagger$ to the undelivered outcome.
No rule of the system reads a coin bit.

\noindent\textbf{4.} \leandeclnamed{decide}{PLTS.ABA.SpecStep.decide} (D13).
Guard $val = \bot$, $SuppOK(s,b)$ and $mode \neq terminal$.
\[ s \xrightarrow{\;\tau\;}
   \delta\bigl(s[\,val := b,\ mode := idle\,]\bigr) \]

\noindent\textbf{5.} \leandeclnamed{ret}{PLTS.ABA.SpecStep.ret}.
Guard $val = b$ and $ret[id] = \mathrm{false}$.
\[ s \xrightarrow{\;\mathrm{retABA}(id,b)\;}
   \delta\bigl(s[\,ret[id] := \mathrm{true}\,]\bigr) \]

\noindent\textbf{6.} \leandeclnamed{fail}{PLTS.ABA.SpecStep.fail} (D1).
Guard $id \notin F$ and $|F| < f$.
\[ s \xrightarrow{\;\mathrm{fail}(id)\;}
   \delta\bigl(s[\,F := F \cup \{id\}\,]\bigr) \]
The guards are the condition under which the transform $\mathrm{corrupt}$ has an effect, so moving them onto the row leaves the effect unchanged and narrows the enabledness alone.

\noindent\textbf{7.} \leandeclnamed{callByz}{PLTS.ABA.SpecStep.callByz} (D23).
Guard $id \in F$.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;}
   \delta\bigl(s[\,input[id] := b'\,]\bigr),
   \qquad b' \in \mathbb{B} \text{ arbitrary} \]
The recorded bit is independent of the one the label declares: a corrupted caller's declared input need not be what is recorded.

\noindent\textbf{8.} \leandeclnamed{retByz}{PLTS.ABA.SpecStep.retByz} (D23).
Guard $id \in F$.
\[ s \xrightarrow{\;\mathrm{retABA}(id,b)\;} \delta(s) \]
A corrupted process returns any bit at any time and the state does not move.
Rule~5 stays available to it, so the two corrupted rules add behaviour and remove none.

\medskip
\noindent Two of the three guards on rule~4 are load-bearing for safety.
Without $val = \bot$ the specification violates Agreement: a second firing rewrites the decision value between two returns, and the two returns carry different bits.
With it, rule~4 being the sole writer of $val$, the decision value is write-once by the shape of the system and not by an invariant.
Without $SuppOK(s,b)$ the specification violates Validity.
Take $n = 4$, $f = 1$, the recorded inputs $1,0,0,0$ and the sole holder of $1$ corrupted.
A decision of $1$ there has every never-corrupted process inputting $0$, and the guard, demanding $f + 1 = 2$ recorded-or-corrupt supporters of $1$, is what rules that trace out.
The third guard, $mode \neq terminal$, carries no safety weight.
It is the D17 outcome: an undelivered flip takes the decision away with every other $\tau$-rule.

\noindent The mixedness guard on rule~3 carries no safety weight either.
It is where the specification holds the liveness half of Validity.
A supported bit has a never-corrupted recorded inputter, by the budget pigeonhole \leandecl{PLTS.ABA.SuppOK.honest_supporter}, so under honest unanimity on one bit the other bit is supported by corrupted identifiers alone, at most $f$ of them, and the guard fails at every state such a run reaches.
The flip is then unreachable, and with it every probabilistic branch of the system, so the unanimous path is Dirac and rule~4 can write only the input.
The guard holds that structurally, in the guard rather than in a proof.

\noindent Rules~7 and~8 constrain nothing.
The bit a corrupted process returns is arbitrary and the state does not move, so no property of the system can constrain such a return; the trace predicates of Theorem~\ref{thm:aba-spec-safe} accordingly quantify over never-corrupted returners.
The write of rule~7 is the one place a recorded bit is replaced.
The support of the value decided survives it, by \leandecl{PLTS.ABA.SuppOK.callByz}: the writer $id$ lies in $F$, so the $F$ disjunct of $SuppOK$ counts it whichever bit it now records.

\dynamics{How a decision arises}{%
Which rule fires is scheduler nondeterminism, resolved by the adversary; the
flip is the only source of randomness.
The flip is enabled at $mode = idle$, with nothing decided, and with each of the
two bits carrying $f{+}1$ support.
One firing resolves into exactly one of three outcomes.
A release leaves the state unchanged, so the flip is enabled again.
A lock sets $mode := locked$, and there the decision is the only $\tau$-rule
the mode can enable, the flip asking for $mode = idle$.
The decision is enabled whenever some bit carries $f{+}1$ support, and a state
that has passed the mixedness guard leaves some bit supported ever after.
The argument runs on the sum of the two support counts and not on either one,
since neither is monotone by itself: rule~1 may overwrite the record of an
uncorrupted identifier, which takes that identifier out of one of the two
supporter sets.
It puts it into the other in the same write, so the sum is unchanged; a write
into an empty entry raises the sum by one; a corruption puts its identifier into
both sets through the $F$ disjunct and raises the sum by one or two; rule~7
writes only at identifiers the $F$ disjunct already counts in both sets, so it
moves neither count.
The sum therefore never decreases.
At the flip it stands at $2f{+}2$ or above, hence at every later state one of
the two counts is $f{+}1$ or above and the decision is enabled at $locked$.
A lock is never discarded.
An undelivered flip sets $mode := terminal$, which enables no $\tau$-rule at all (D17), so an
undelivered flip leaves the system with no decision and no return.

The three masses read as a liveness statement, which is stated here and not
proved in Lean.
Each firing locks with probability $\varepsilon$ and excludes with probability
$\failmass$.
A run that keeps flipping therefore locks or dies almost surely, and under a
scheduler that fires nothing but the flip it locks with probability
$\varepsilon/(\varepsilon+\failmass)$.
No safety argument uses either mass.
The reading is conditional on the guard: a run on which one bit is never
supported never flips at all, and every state it reaches has a Dirac successor
distribution.
That is the unanimous case, and it is the liveness half of Validity: under
honest unanimity on $v$ the run cannot flip, cannot lock, cannot die, and rule~4
can write only $v$.
The decision is \emph{enabled}, never forced, and the scheduler may decline it
forever, so the claim that the protocol decides with probability $1$ under fair
scheduling is a separate statement, not proved here.

The corrupted interface is arbitrary and influences nothing.
Rule~8 leaves the state fixed, and rule~7 writes only where the $F$ disjunct
already counts its identifier at both bits, so neither rule changes which bits
are supported, which mode the system is in, or what value rule~4 may write.
What they add is trace behaviour, which is why the properties are read at
never-corrupted returners.

The flip names no coin bit.
Reading a lock as the coin agreeing with the round's reference value is an
outcome coupling carried by a refinement, not a component of Transition
System~1.
}

\dynamics{Binding as negative information}{%
An instance binds by removing an option rather than by choosing one.
The only writer of $excluded$ is \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset}, which inserts, and it fires
from the empty set only, so $excluded$ grows along every execution and one bit is
excluded per instance.
Corruption does not touch the field.
Every property below is a consequence of that monotonicity together with the
membership guards on the returns, with no auxiliary invariant.
Both value-bearing returns carry the same guard pair, $v \notin excluded$ and
$1-v \in excluded$: the bit handed out is alive and the other bit is already excluded.
That pair is Graded Agreement.
A return of $v$ pins $1-v$ into $excluded$; monotonicity carries that membership to
every later state of the run; a later return of $w$ needs $w \notin excluded$, so
$w \neq 1-v$, so $w = v$.
Two returns of one execution therefore name the same bit whatever their grades,
and once any value-bearing return has fired a single bit is the only one any
extension can ever hand out.
The $C$-return's guard $|excluded| \ge 1$ is the Binding clause read on this state:
a member of $excluded$ is a bit that no correct process is handed at grade $\ge 1$
in any extension, because the value-bearing returns cannot hand out an excluded bit and
$excluded$ only grows.
A $C$-return therefore commits the instance --- from that point at most one bit
is alive anywhere in the future --- which is what makes handing out no bit the
right answer, and it is why every return, $C$-returns included, requires an exclusion
to have happened.
}

\dynamics{Why the exclusion is once-only}{%
The guard $excluded = \emptyset$ on \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset} is what keeps every round
completable.
Let us see what a second exclusion would cost.
Suppose the rule were enabled again after an $A$-return of $v$, and fired on
$v$ itself.
The processes yet to return would then have no return available: the
value-bearing returns need a live bit, and there is none, while the $C$-return
is blocked by the $A$ grade guard.
The round would be stranded, and a fair scheduler could not complete it.
Under the once-only guard no such state is reachable.
A round that has answered one process at grade $\ge 1$ can answer every other
process the same way, since the surviving bit stays alive and the $A$ grade guard
admits further $A$- and $B$-returns.
}

\dynamics{What the contract asks and what is proved here}{%
The GBCA contract listed at the start of this case study has four clauses.
The specification instance settles two of them outright and the safety half of
a third.
Graded Agreement is the guard pair on the value side and the grade guard on the
grade side, both structural (Theorem~\ref{thm:gbca-spec-binding}).
Binding is the $C$-return guard read through monotonicity, again a theorem of
the same statement.
Validity has a safety half, that under unanimous honest input $v$ every return
of the instance hands out $v$ and no $C$-return occurs, and that half is
Theorem~\ref{thm:gbca-spec-validity}.
What the clause asks beyond that half --- that the grade is the top one, and
that every correct process is answered at all --- is a statement about which
runs the scheduler must extend, as is Termination.
Fairness is not encoded here, so those clauses lie outside this development.
}

\dynamics{What the grades promise}{%
The grade records how much of the round its holder is committed to.
An $A$-return commits to the surviving bit and is the grade that licenses a
decision.
A $B$-return carries the surviving bit as the next estimate but records that
dissent was seen.
A $C$-return carries no value, and its holder falls back on the coin.
The $A$ and $C$ grade guards are mutually exclusive: once an $A$-return has
occurred no $C$-return is enabled at that instance, and once a $C$-return has
occurred no $A$-return is.
The exclude, the dissenting bit at a $B$-return and each of the two bits at a
$C$-return are guarded by $f+1$ distinct supporters, counted $F$-blind, so the
count is monotone in $F$ and immune to later corruptions.
At most $f$ processes are ever corrupted, so any such set of $f+1$ contains a
member outside the final corrupted set, hence a never-corrupted genuine caller.
That member is the witness which carries Validity down to a caller: a bit $v$
handed out at grade $\ge 1$ requires $1-v \in excluded$, and the exclusion that put it
there certified $f+1$ $F$-blind supporters of $v$ itself.
}

\dynamics{The coin and its parameters}{%
One coin resolution has four outcomes.
With probability $\varepsilon$ the outcome is the bit $0$, and with probability
$\varepsilon$ it is the bit $1$.
In either case every correct process receives that bit.
With mass $1 - 2\varepsilon - \failmass$ the outcome is $\top$, the unresolved
coin: each process may then be handed either bit by the adversary,
independently of the others.
With probability $\failmass$ the outcome is $\dagger$, on which the resolution
delivers to no process at all (D17).
The outcome $\dagger$ models a delivery failure of the implementation this
specification stands for.
That implementation reconstructs the coin from an $\varepsilon$-correct
verifiable secret sharing, and the reconstruction can fail; on failure the coin
delivers nothing.
The two non-bit outcomes are distinct at the interface.
On $\top$ the coin delivers, and the adversary only picks which bit each
process receives.
On $\dagger$ no delivery occurs, and the callers of that instance hold no
return to read.
Transition System~3 is a specification, not an implementation.
The $\varepsilon$-Goodness it asserts is an assumption of this development, to
be discharged by an implementation over Gather and SRSD that is not modelled
here.
The assumption is inert for the results proved: safety holds for every
admissible pair $\varepsilon, \failmass$, including $\varepsilon = 0$, where the
coin resolves to $\top$ or $\dagger$ almost surely.
Safety is insensitive to $\failmass$ for a further reason: the outcome $\dagger$
removes returns rather than adding any, and every safety property of this
development constrains the returns that do occur.
It is a termination argument that would consume the $\varepsilon$-mass, and
such an argument must carry the $\failmass$-mass too, since a $\dagger$ resolution
produces no return at all.
Termination and fairness are out of scope.
}


\section{The protocol reading}
\label{sec:aba-protocol-reading}


What runs is $n$ programs, a network adversary and a coin oracle.
Each program is one process: its round loop, the graded-agreement stage record
of the round that loop is in, and the messages that have been delivered to it.
What it holds of corruption is one flag, saying whether its own program has been
replaced (D23).
No field of its record is a copy of the corrupted set, none is the corruption
budget, none names another process's status, and none records what the process
has multicast, so no guard of its rule table can ask whether another process is
honest or what this one has sent.
The network adversary holds exactly what a process may not see: the message
sent sets of every sender, the DECIDED sets, and the corrupted set together with
the corruption budget.
It takes part in every send, in every delivery, and in every authorisation of
off-protocol behaviour.
The coin oracle is the weak common coin, which this development holds at
specification level (Transition System~3).
The round loop and the graded-agreement stage make up the programs, and this
section gives them in the form they run in: the automaton of one process, every
guard of which reads that process's own record, beside the adversary that holds
the rest.
Section~\ref{sec:aba-abdy} gives the same two again at ABDY22's implementation, as
pseudocode and then as rule inventories in which a guard is read against the
line of pseudocode it transcribes.
Each inventory enters the argument at a named point.
Each is one automaton read on the pair of components that hold its own state.
The graded-agreement inventory is read on the $n$ stage records beside the
round's message state, which is the state one round instance runs on, and
that is how the refinement proved of it transports
(Theorem~\ref{thm:aba-subsim}).
The round-loop inventory is read on the round-loop records beside the DECIDED
network, which is the state the core simulation's relation is defined on
(Theorem~\ref{thm:aba-hybrid-spec}).
In both cases the network is a component of the state and not a field of a record,
so a rule of the inventory and a rule of the composition are written against the
same object.

Algorithm~\ref{alg:gbca-impl} is the graded-agreement stage of one process and
Algorithm~\ref{alg:aba-core} the round loop that calls it, with one stage
instance and one coin instance per round.
Instance identity is carried on the messages: in the cited paper every message
bears a tag $id$ naming the instance it belongs to, and the encoding carries
that tag as the round index $r$ on the stage labels, on the message sets
$sent(r,j)$ and on the round-tagged sub-protocol handshakes.


A process holds nothing of the corruption state.
No honest rule reads the corrupted set, and each Byzantine rule
asks only whether the process it belongs to is corrupted --- a question about
what the environment may do, not about the process's own data.
The program below therefore carries neither that set nor a bit standing in for
it, and the question is answered at the network adversary, whose guard
$k \in F$ is the whole authorisation of an off-protocol step.

What the program does carry is the local effect of such a step.
A Byzantine call opens the process's stage record exactly as an honest call would,
and a Byzantine return marks that record returned under the same receipt evidence.
The sub-protocol ports are input-enabled in that sense: a process can refuse
neither a call nor a return, and cannot tell an authorised one from an honest
one.
Only the choice of which handshake rows are available is the environment's.

The three components are composed by full synchronisation, communicating
through send, delivery and handshake-row labels that the composition hides.
The programs are composed by the product of Definition~\ref{def:syncproduct},
taken over the extended alphabet of Definition~\ref{def:relabel} and read back
along the restriction that definition supplies.
The record of one automaton holds that process's own rows and nothing further,
so locality sits in the state shape and not in the guards alone.

None of this depends on how graded agreement is implemented.
The round loop, the DECIDED relay and its delivery, the coin handshake, the
corruption discipline, the adversary's table and the composition pipeline are
fixed by the round interface and the specification, and what an implementation
supplies is its stage message type, its per-process per-round stage record and
its stage-side rows.
The reading is therefore written once, parametric in those three, and
instantiated here at the implementation of Algorithm~\ref{alg:gbca-impl};
Section~\ref{sec:aba-gather} instantiates it a second time.
The rendezvous alphabet is parametric in the message type, and is hidden before
anything outside the composition sees it, so two instantiations need not agree
on it.

A system below the meeting point of the two chains therefore belongs to one
implementation or the other, and carries a superscript naming its source:
$\abdy{\mathrm{protocol}}(P)$ and $\abdy{\mathrm{composed}}(P)$ here, after the
authors of~\cite{ABDY22}, and $\afw{\mathrm{protocol}}(P)$ and
$\afw{\mathrm{composed}}(P)$ in Section~\ref{sec:aba-gather}, after those
of~\cite{AFW25}.
The systems the two chains share, $\mathrm{hybrid}(P)$ and $\mathrm{spec}(P)$,
carry none.
The Lean development writes each superscript as a namespace.

The Lean encoding of Algorithm~\ref{alg:gbca-impl} is the round-$r$ instance
$\mathrm{GBCA.implInst}$, an LTS over the shared label alphabet of the
development.
Fix the parameters $n$ and $f$ with $3f < n$.
Write $[n]$ for the process identifiers and $F \subseteq [n]$ for the corrupted
set.
The message type is
\[ \begin{aligned}
     \mathrm{Msg} \;=\;
     &\{\,\langle\mathrm{INPUT}, b\rangle,\ \langle\mathrm{ECHO}, b\rangle
       \;:\; b \in \{0,1\}\,\}\\
     &{}\cup\;
     \{\,\langle\mathrm{VOTE}, v\rangle,\ \langle\mathrm{BIND}, v\rangle,\
       \langle\mathrm{ECHO5}, v\rangle \;:\; v \in \{0,1,\bot\}\,\}.
   \end{aligned} \]
Every rule of the instance is Dirac.
A rule is therefore determined by its guard and its state update, and the table
below carries no distribution column.

The local state of one process is the record $\mathrm{ProcState}$, \leandecl{PLTS.ABA.GBCA.ProcState}, with fields
\begin{itemize}
  \item $\mathit{input}$ --- the bit supplied by the environment call; unset
    before the call.
  \item $\mathit{sentInput} : \{0,1\} \to \{\text{true},\text{false}\}$ --- which
    $\mathrm{INPUT}$ payloads this process has multicast.
  \item $\mathit{sentEcho}$ --- the $\mathrm{ECHO}$ payload multicast; unset if
    none, and written at most once.
  \item $\mathit{sentVote}$ --- the $\mathrm{VOTE}$ payload multicast; unset if
    none, and the recorded payload may itself be $\bot$.
  \item $\mathit{sentBind}$ --- the $\mathrm{BIND}$ payload multicast, on the
    same convention.
  \item $\mathit{sentEcho5}$ --- the $\mathrm{ECHO5}$ payload multicast, on the
    same convention.
  \item $\mathit{returned}$ --- whether this process has returned from the
    instance.
\end{itemize}
The state of the instance is not a record of its own.
It is the pair
\[
  \mathrm{ImplState}(n) \;=\;
    \bigl([n] \to \mathrm{StageRec}(n)\bigr) \times \mathrm{GNetState}(n),
\]
\leandecl{PLTS.ABA.GBCA.ImplState}: the $n$ stage records of
Definition~\ref{def:aba-procnet}, each holding one process's $\mathrm{ProcState}$ beside the messages delivered to it, and the round's message state of Definition~\ref{def:aba-gbcasub}, holding the per-sender sent sets and the corrupted set.
The rules below are written in four accessors on that pair.
\begin{itemize}
  \item $\mathit{proc} : [n] \to \mathrm{ProcState}$ --- the local states, read
    off the stage records.
  \item $\mathit{sent} : [n] \to \mathcal{P}(\mathrm{Msg})$ --- the message state's
    sent sets: $\mathit{sent}(j)$ is the set of messages $j$ has multicast (D5).
  \item $\mathit{recv} : [n] \times [n] \to \mathcal{P}(\mathrm{Msg})$ ---
    $\mathit{recv}(i,j)$ is the set of $j$'s messages the adversary has delivered to $i$, read off $i$'s own stage record (D5).
  \item $F$ --- the message state's corrupted set, held in lockstep with the other
    components by the $\mathrm{fail}$ broadcast.
\end{itemize}
Multicasts are idempotent and thresholds count distinct senders, so message duplication and point-to-point scheduling are absorbed into the set model (D5).
Three derived quantities occur in the guards.
Set
\[
  \#_i(m) \;=\; |\{\, j \in [n] \;:\; m \in \mathit{recv}(i,j) \,\}|,
  \qquad
  \mathit{Val}_i \;=\;
    \{\, b \in \{0,1\} \;:\; \#_i(\langle\mathrm{INPUT}, b\rangle) \ge n - f \,\},
\]
and write $\#_i(\mathrm{EC})$, $\#_i(\mathrm{VT})$, $\#_i(\mathrm{BD})$, $\#_i(\mathrm{SL})$ for the payload-blind counts, that is, the number of distinct senders from which $i$ holds some $\mathrm{ECHO}$, some $\mathrm{VOTE}$, some $\mathrm{BIND}$, some $\mathrm{ECHO5}$.
The set $\mathit{Val}_i$ is Algorithm~\ref{alg:gbca-impl}'s variable $\mathit{Valid}$, read off the delivered messages instead of being stored, so the condition $|\mathit{Valid}| > 1$ becomes $\mathit{Val}_i = \{0,1\}$.
In the table $\mathrm{IN}\,b$, $\mathrm{EC}\,b$, $\mathrm{VT}\,v$, $\mathrm{BD}\,v$ and $\mathrm{SL}\,v$ abbreviate the five message forms, ``mcast'' abbreviates the insertion of a message into the sender's $\mathit{sent}$ sent set, and a dash marks an unguarded rule.
The two $\mathrm{ECHO5}$ rows and the ECHO5-reading guards of the three return rows are what D18 restores over the source blueprint's compressed four-round form, and carry no separate marker in the table.
Two further conditions of Algorithm~\ref{alg:gbca-impl}'s control flow are written into the same guards and are likewise unmarked: from the $\mathrm{BIND}$ level down each level asks for the process's own send at the level below, and each return denies the cases above it.
The two $\mathrm{VOTE}$ rows ask for no own send, the $\mathrm{ECHO}$ they read being multicast by an \textbf{upon} handler and not in the body of the algorithm.

The four \textbf{wait until} blocks of Algorithm~\ref{alg:gbca-impl} are the guards of \leandeclnamed{voteBit}{PLTS.ABA.GBCA.ImplStep.voteBit}/\allowbreak\leandeclnamed{voteBot}{PLTS.ABA.GBCA.ImplStep.voteBot},

\leandeclnamed{retA}{PLTS.ABA.GBCA.ImplStep.retA}/\allowbreak\leandeclnamed{retB}{PLTS.ABA.GBCA.ImplStep.retB}/\allowbreak\leandeclnamed{retC}{PLTS.ABA.GBCA.ImplStep.retC}; the write-once fields
$\mathit{sentEcho}$, $\mathit{sentVote}$, $\mathit{sentBind}$, $\mathit{sentEcho5}$ carry the ``not sent yet'' side conditions.
The blocks are taken in the order Algorithm~\ref{alg:gbca-impl} writes them.
A process reaches a block only after executing the send the block above it ends with, and that is the guard $\mathit{sentVote}_j$ set on the two $\mathrm{BIND}$ rules, $\mathit{sentBind}_j$ set on the two $\mathrm{ECHO5}$ rules, and $\mathit{sentEcho5}_i$ set on the three return rules.
The two $\mathrm{VOTE}$ rules carry no such guard.
What precedes the first \textbf{wait until} block is not a block a process must execute to the end but the \textbf{upon} handler that multicasts $\mathrm{ECHO}$, so a process may reach that block with its own $\mathrm{ECHO}$ still pending.
In each of the three return blocks the two rules are exclusive: the $\bot$ rule denies its block's case (a) at either bit, which is the \textbf{else} of that block's last line.
The three return rules are the three wait-until cases of the last block: case (a) is an $n{-}f$ $\mathrm{ECHO5}\,v$ quorum, case (b) an $n{-}f$ any-$\mathrm{ECHO5}$ quorum containing $\mathrm{ECHO5}\,v$ together with $f{+}1$ $\mathrm{BIND}\,v$ receipts and $|\mathit{Valid}| > 1$, and case (c) an $n{-}f$ $\mathrm{ECHO5}\,\bot$ quorum with $|\mathit{Valid}| > 1$.
That block ends in an \textbf{if}/\textbf{elif}/\textbf{else}, so each rule carries the denials of the cases above it beside the receipts its own case names: \leandeclnamed{retB}{PLTS.ABA.GBCA.ImplStep.retB} denies case (a) at either bit, and \leandeclnamed{retC}{PLTS.ABA.GBCA.ImplStep.retC} denies case (a) at either bit and case (b).
The denial of case (b) is carried in reduced form.
Case (b) asks at a bit $v$ for four things: an $n{-}f$ any-$\mathrm{ECHO5}$ quorum, a received $\mathrm{ECHO5}\,v$, $f{+}1$ $\mathrm{BIND}\,v$ receipts and $|\mathit{Valid}| > 1$.
The first and the last are supplied by
\leandeclnamed{retC}{PLTS.ABA.GBCA.ImplStep.retC}'s own guard, an $n{-}f$
$\mathrm{ECHO5}\,\bot$ quorum being in particular an $n{-}f$ any-$\mathrm{ECHO5}$ quorum, so what is left to deny is the pair of the received $\mathrm{ECHO5}\,v$ and the $f{+}1$ $\mathrm{BIND}\,v$ receipts.
All three rules ask further that the returning process has been called, the D8 guard carried from the sends over to the returns.
Case (c) returns no bit.
The depth is what the grade-$1$ evidence buys (D18): $f{+}1$ $\mathrm{BIND}\,v$ receipts exceed the corruption budget, so they put an honest $\mathrm{BIND}\,v$ sender behind every grade-$1$ output, and that sender's own wait condition is an $n{-}f$ $\mathrm{VOTE}\,v$ quorum over the write-once $\mathrm{VOTE}$ level --- the object the binding argument of~\cite{ABDY22} counts.
The prose preceding Algorithm~6 in~\cite{ABDY22} says ``upon receiving $\mathrm{echo4}$ messages from $2t+1$ parties'' where its own pseudocode says $n - t$.
The two coincide only at $n = 3t+1$, and the encoding follows the pseudocode, $n - f$.
The $excluded$ and $grade$ fields of Transition System~2 are abstractions of these receipt patterns and belong to the specification alone; Theorem~\ref{thm:gbca-inst-refines} supplies them from the receipts.

The inventory above is one rule table, and the composition of Definition~\ref{def:aba-gbcasub} is $n$ programs beside a message state.
They are two presentations of the same round on the same state, and each rule of the table is a rule of the composition with its participants named.
A rule that touches both halves is a rendezvous:
\leandeclnamed{deliver}{PLTS.ABA.GBCA.ImplStep.deliver} reads the message state's sent set
in its guard and writes the receiver's row, so it splits into the two halves of a $\mathrm{gdlv}$ rendezvous, the message state supplying the guard $m \in \mathit{sent}(j)$ and the receiver performing the row update.
No rule reads a second process, and Definitions~\ref{def:aba-procnet} and~\ref{def:aba-netadv} are where each guard is written against one process record.

\dynamics{What is distributed and what is not}{%
Calling the encoding a distributed algorithm is a claim about which state a
rule is allowed to read, and the presentation states it in its sharpest form.
Every implemented part of the protocol is $n$ programs: the round loop, the
graded-agreement stage of each round, the DECIDED gossip and the receipt
bookkeeping of both sit inside $\mathrm{ABAProcN}(P,j)$, and every guard
of its forty-three rules is a function of $j$'s record.
Nothing of the protocol is shared.
The receipt rows and the control records each belong to one process, and every
quorum count is taken over one process's rows.
What a process holds of corruption is one bit of its own record, saying whether
its own program has been replaced (D23); the corrupted set, the budget and every
other process's status are outside its table.
Two components are not programs, and each is centralized for its own reason.
The first is the network adversary.
It is not part of the protocol: it is the environment the protocol runs in, and
it holds what a process is not entitled to see --- who has multicast what, who
is corrupted, and how much corruption is left.
Putting the message sets there rather than in outboxes is what makes a
process's blindness to its own sends structural, and putting the corrupted set
there with its guard $k \notin F \wedge |F| < f$ makes the corruption budget a
component's guard rather than a side condition on the executions the adversary
may produce.
The second is the coin oracle, and it is centralized of necessity.
An $\varepsilon$-common coin is a correlation between processes: the assumption
is that with probability at least $\varepsilon$ the processes of a round read the
same bit.
A correlation is not a property of any one process's state, so no assignment of
the oracle's transitions to per-process rules expresses it.
Writing the oracle as $n$ programs would mean supplying the protocol that
produces the correlation, which is the sub-protocol this development assumes
rather than proves.
It is also the one component whose transitions are not Dirac, and it occupies the
same coordinate in every system of the argument, from the protocol to the
composition the core simulation runs on.
}


\subsection{The composed reading}

A sub-protocol may be replaced by its specification where it is a component of a composition, and nowhere else.
The protocol of Definitions~\ref{def:aba-procnet} and~\ref{def:aba-protocol} does not present graded agreement as a component.
Each program runs the round loop and the graded-agreement stage of every round it has touched, and the single network adversary holds the message sets of both.
This subsection reads the same protocol as a composition of components, and Theorem~\ref{thm:aba-protocol-composed} carries the protocol into it.
The link is an inclusion, and the component boundary is where the chain passes from implementation to specification: below it is the system that runs, and above it everything is specification.
A composed state carries one graded-agreement instance per round at every moment, so the message state of every round survives there as specification-side state that no process holds, and a round instance, carrying no termination flag, answers a send or a delivery at a process the protocol has terminated (D22).
Graded agreement is a parallel component of that reading, and that is what the substitution congruence consumes.

The cut is decided by one question: which network does a component own?
A round of graded agreement is a replaceable component exactly when the round's message state belongs to that component --- the records its stage messages sit in, the guard that lets one be delivered, and the injections a corrupted sender makes into it.
The instance of Definition~\ref{def:aba-gbcasub} is drawn to own it.

Each process carries a handshake phase, an element of
\[
  \mathrm{Phase} \;=\;
  \{\,\mathrm{idle},\ \mathrm{toCallG},\ \mathrm{awaitG},\ \mathrm{toCallW},\

\]
traversed as $\mathrm{idle} \to \mathrm{toCallG} \to \mathrm{awaitG} \to \mathrm{toCallW} \to \mathrm{awaitW} \to \mathrm{toCallG} \to \cdots$.
There is no separate phase for the per-round bookkeeping between the WCC return and the next GBCA call, because that bookkeeping is fused into the $\mathrm{retW}$ step (D10).
The per-process record $\mathrm{ProcCore}$, \leandecl{PLTS.ABA.ProcCore}, has fields
\begin{itemize}

    $\mathrm{callABA}$.
  \item $\mathit{est}$ --- the current estimate; the value $\bot$ is

  \item $\mathit{round} \in \mathbb{N}$ --- the current round, counted from $0$
    (D9).
  \item $\mathit{phase} \in \mathrm{Phase}$ --- the handshake phase.
  \item $\mathit{lastGrade}$ --- the graded outcome of the current round's GBCA;
    unset before the return, and cleared by the round advance.
  \item $\mathit{returned}$ --- whether $\mathrm{retABA}$ has fired at this
    process.
\end{itemize}
The state a rule of the inventory moves is $\mathrm{ABAState}(P)$,
\leandecl{PLTS.ABA.ABAState}, read by the four accessors
\begin{itemize}
  \item $\mathit{procs} : [n] \to \mathrm{ProcCore}$ --- the control records,
    each at its own process's round-loop record.
  \item $\mathit{decidedRecv} : [n] \times [n] \to \mathcal{P}(\{0,1\})$ ---

  \item $\mathit{decidedSent} : [n] \to \mathcal{P}(\{0,1\})$ ---
    $\mathit{decidedSent}_j$ is the set of $\mathrm{DECIDED}$ payloads $j$ has multicast, held at the network (D12$'$).
  \item $F$ --- the corrupted set, held at the network and kept in lockstep

\end{itemize}
The first two are process-local and the last two are the network's, which is what makes a process blind to its own sends, to the corrupted set and to the budget.

Membership of $F$ is tested at the network alone: by the four Byzantine handshake rows, by $\mathrm{byzD}$, and by the Byzantine return row.
A round loop reads its own replacement flag and no more, so no rule of it names the corrupted set, the budget, or another process's status (D23).
The honest return row is the notable case: an unreplaced program must pass the same $n - f$ DECIDED count whether or not its process is in $F$, and the specification's rule~5 is likewise blind to honesty.
What a corruption buys at the interface is the row beneath it, which asks for no DECIDED evidence at all.
The corruption rule \leandeclnamed{fail}{PLTS.ABA.Comp.ANetStep.fail} is a synchronisation of every component of the composition, each keeping its own copy of $F$; at the process it names the round loop's half is \leandeclnamed{failSelf}{PLTS.ABA.Comp.CoreProcStepN.failSelf}, which writes the replacement flag, and at every other process it is \leandeclnamed{failIdle}{PLTS.ABA.Comp.CoreProcStepN.failIdle}, another process's corruption being no business of theirs.

\dynamics{The round loop}{%
Each process runs a five-phase cycle: idle, ready to call the round's GBCA,
awaiting its return, ready to call the round's coin, awaiting the coin.
The graded outcome fixes the next estimate, an $A$- or $B$-return of value $b$
setting it to $b$ and a $C$-return clearing it to $\bot$; a cleared estimate is
filled by the coin of the same round, and a set estimate ignores that coin.
When the round's grade was $A\,b$, the step that receives the coin also
multicasts $\langle \mathrm{DECIDED}, b \rangle$ and advances the round.
A process holding $\langle \mathrm{DECIDED}, b \rangle$ from $f+1$ distinct
senders and not having multicast $\langle \mathrm{DECIDED}, b \rangle$ itself multicasts
$\langle \mathrm{DECIDED}, b \rangle$ itself, the $f+1$ threshold guaranteeing
one honest sender behind any echo.
The return rule requires $\langle \mathrm{DECIDED}, b \rangle$ from $n-f$
distinct senders together with the returning process's own prior multicast
of $b$.
The $n-f$ count is what excludes disagreement: two returns of different bits
would need two sender sets of that size, and any two such sets meet in more
than $f$ processes, hence in an honest one.
The own-multicast clause makes every return the endpoint of a diffusion its
own holder joined.
That an honest process never sends both payloads is not a property of the round
loop in isolation --- nothing in its rules forbids two $A$-grades of opposite
bits in different rounds --- but of the composition, where Graded Agreement on
the GBCA family rules that pair out; the round loop alone guarantees only that
each process returns at most once, by the flag its return rule sets.
}

\dynamics{What the idealisation removes and what it leaves}{%
The substitution replaces one component, and the component is a round of graded
agreement together with that round's message state.
Everything the message state holds goes with it.
The stage sent sets disappear, and with them the guard $m \in sent(j)$ that made a
delivery sound, the write-once fields that recorded a multicast, and the
injection $\mathrm{byzG}$ by which a corrupted sender put an arbitrary stage
message into circulation.
The round specification has none of these: it has call entries, an exclusion set,
and graded returns.
What survives is everything the other three components hold.
The DECIDED sets keep their own delivery guard and their own Byzantine
injection, at the ABA-side network.
The corrupted set survives there too, with the budget $|F| < f$ as the guard on
the $\mathrm{fail}$ row, and so does the authorisation $k \in F$ of every
Byzantine handshake row --- including those of the graded-agreement,
whose effect is inside the replaced component and whose authorisation is not.
The asymmetry is decided by the cut and not by the argument: a Byzantine power
vanishes under an idealisation exactly when it is a power over the network the
idealised component owns.
This also fixes what it would take to vary the network's power.
A weaker message state --- lossy delivery, a bound on injection, authenticated
channels of a different strength --- is a different system in the same position,
and it enters the chain by the same precongruence, with the round loops, the
DECIDED sets, the corrupted set and the coin oracle untouched.
The strength of the network is therefore a component that can be replaced, and
no proof outside that component depends on it.
}

Reliable broadcast is the bottom layer, and its specification is the first point dynamic corruption shapes.
Under Transition System~6 an honest call pins every return to the called value, and Algorithm~\ref{alg:brb} with the leader corrupted after its $\mathrm{INIT}$ leaves a window that pinning forbids: until some correct process holds an $n{-}f$ $\mathrm{ECHO}$ quorum, the injections of the now-corrupted leader can make the rounds deliver a different value.

\subsection{Gather}


Gather has every process broadcast a payload and returns to each caller a set of (process, payload) entries; the binding guarantee is that the returns share a committed core fixed no later than the first of them.
The specification holds that content as a write-once \emph{family} of entry sets, any two of which share at least $n - f$ entries, every return dominating some member (D25).
The single core of the classical statement is the family's intersection, and its $n - f$ size bound is a fact about complete executions rather than a predicate of reachable states: at $n = 3f + 1$ a state at the first return has as few as $n - 2f$ honest votes cast, and fixes no single $n{-}f$-sized set every future return must dominate --- \cite{AFW25}, Remark~22, reads the core of a gather without binding as determined only in hindsight.
The family of committed $\mathrm{BIND}$ payloads is what such a state does determine: each payload is backed by an $n{-}f$ $\mathrm{VOTE}$ quorum, two quorums share an honest voter, and that voter's write-once vote of $n - f$ entries sits below both payloads, which is the pairwise bound.
Sending the $\mathrm{BIND}$ payload by reliable broadcast rather than on the message state is what makes ``committed'' meaningful under dynamic corruption: a broadcast value is write-once whatever later happens to its sender, where a message state multicast from a sender corrupted later pins nothing.
The commit split of D26 is the per-entry form of the same reading.

The implementation is verified in two substitutions.
The gather-over-broadcast reading embeds the $2n$ broadcast specifications as state coordinates and is carried to Transition System~4 by the core refinement, whose returns are answered by one weak run --- the abstract commits, the binding where the family is unbound, the return --- with the fresh family read off the committed $\mathrm{BIND}$ payloads of the $f{+}1$ honest members of the returning quorum.
The fully concrete reading replaces each broadcast coordinate by a Bracha instance and is carried to the previous one coordinatewise, the lagging specification commits fired as $\tau$-chains under the rows that read them.

\subsection{The two-gather round}


The round is Algorithm~\ref{alg:gbca-gather} over the round alphabet: the call is the first gather's call, the link from the first return to the second call computes the candidate, and the graded return reads the second gather's counts (D24).
The refinement into Transition System~2 is counting on the two core families, in member form.
A returned map heavy at a value --- all but $f$ entries --- makes every family member heavy at it; two heavy members agree, their $\ge n - f \ge 2f + 1$ shared entries admitting one value on all but $2f$; and a member heavy at one value leaves every other value at most $f$ entries anywhere, which is at once the uniqueness of the $B$-bit and the $A$/$C$ exclusivity of the grade guard.

\section{The gather-based chain}


Beneath the composed reading is the protocol that runs.
It is the reading of Definition~\ref{def:aba-flat-reading} a second time, at the gather-based implementation: the same round loop, the same DECIDED sets, the same coin handshake, the same corruption discipline and the same pipeline, over a stage side that is the two gather instances and the $4n$ Bracha instances beneath them.
Two rearrangements separate that stage side from the composed reading's, and both are forced by what a flat reading is.
A round of the composed reading carries $4n+2$ message states, one per sub-protocol instance, while the adversary of a flat reading carries one sent-set family per round; a stage message therefore carries a tag naming the message state it belongs to, and for a broadcast message the instance, whose index is its leader.
The sender index stays the sender, so a threshold still counts distinct senders (D5).
And the composed reading indexes the local states by instance and then by process, while a program must hold its own data and no one else's; the stage record is therefore transposed, holding one process's local state in every instance.
Neither rearrangement loses anything, because every guard of the gather-based implementation reads the acting process's own local states and the message states, and the two rows that read a message state --- the adversary's delivery and its Byzantine injection --- belong to the adversary in either reading.
Assembling the composed state from the flat one undoes both: the local states are transposed back, and each message state is sliced out of the tagged sent-set family.
That assembly is the simulation relation of Theorem~\ref{thm:aba-afw-protocol-composed}, which is a function rather than a correspondence --- the composed state is computed from the flat one, and the proof obligation of a row is which of the six slices takes the message it sent sets.
See \leanmodule{Leslie2Protocols/ABA/AFW/Flat} and
\leanmodule{Leslie2Protocols/ABA/AFW/FlatSim}.

\blueprintfig{fig-afw-protocol}{The gather-based protocol \leandecl{PLTS.ABA.AFW.protocol}: the $n$ programs beside the one network adversary and the coin oracle, under the two hiding frames of Definition~\ref{def:aba-flat-reading}.
The shape is the flat reading's, and two things distinguish it from ABDY22's instantiation.
The adversary holds a single sent-set family per round over the tagged message type \leandecl{PLTS.ABA.AFW.Msg}, whose tag names the message state a message belongs to and, for a broadcast message, the instance; the composed reading of the same round carries $4n + 2$ separate message states.
And a program's record is process-major: process $j$ holds its own local state in every instance, where the composed reading indexes the local states by instance and then by process.
Assembling the composed state from the flat one undoes both, which is what \leandecl{PLTS.ABA.AFW.toPair} does --- slicing the one sent-set family into the message states, and transposing the records back.}



At the protocol shape the gather-based rounds occupy the same refinable position the direct rounds do.
Each reading of the round is lifted over the extended alphabet along the label pullback of Definition~\ref{def:aba-gbcasub} --- the read-back congruence transports each per-round simulation with no further proof obligation --- and gathered into the round-indexed family under the corruption broadcast, whose compatibility is each relation's own lockstep statement.
The three family substitutions run under the composed reading's context through the four congruences, exactly as the substitution of Theorem~\ref{thm:aba-substitution} does, and the third stage lands on $\mathrm{hybrid}(P)$ itself: the core simulation, the safety of the specification and the safety transfer are shared between the two chains from that point up.
One specification, two verified implementations, one meeting point at $\mathrm{hybrid}(P)$. Below that point the chain has one step more than the direct one, the substitution splitting into its three stages:
\[
  \afw{\mathrm{protocol}}(P)
  \;\sqsubseteq\; \afw{\mathrm{composed}}(P)
  \;\sqsubseteq\; \afw{\mathrm{hybrid}}_1(P)
  \;\sqsubseteq\; \afw{\mathrm{hybrid}}_2(P)
  \;\sqsubseteq\; \mathrm{hybrid}(P)
  \;\sqsubseteq\; \mathrm{spec}(P).
\]
The first step is Theorem~\ref{thm:aba-afw-protocol-composed}, the middle three are the stages of Theorem~\ref{thm:aba-afw-substitution}, and the last is Theorem~\ref{thm:aba-hybrid-spec}, shared with the direct chain.
See \leanmodule{Leslie2Protocols/ABA/AFW/Chain}.
