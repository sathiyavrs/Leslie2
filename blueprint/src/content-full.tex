\subsection{Erasing a state component}

A system is often written with a state component that no transition's firing depends on, carried so that an invariant can be stated over it, and read at most to decide a value a step announces.
A component of that kind is an auxiliary variable in the sense of Abadi and Lamport~\cite{AL91}, and erasing it must leave the observable behaviour untouched.
The definition below states that for systems whose steps are distributions.
One clause projects every step of the system carrying the component onto a step of the system without it, on the same label; a second answers every step of the system without the component by a step of the system carrying it that projects back onto it.
The two together give equality of achievable trace distributions, where a simulation alone gives an inclusion.
The clauses are the functional matching of Lemma~\ref{def:strongfunctional} and its converse, so the equality rests on Theorem~\ref{thm:forward-sound} and on nothing further.
Congruences carry an erasure through parallel composition, abstraction and restriction, so it composes as a simulation does, and the case study uses it in exactly that way.
The construction is in \leanmodule{Leslie2Protocols/Framework/Erasure}.

\chapter{The ABA case study}


This section is a case study: the verification of an implementation of Asynchronous Byzantine Agreement against a small specification, by probabilistic forward simulation, built on the five results proved above.
The setting is $n$ processes, each holding an input bit, of which at most $f$ are Byzantine, with $3f < n$, communicating by asynchronous message passing.
The development is in the opt-in \texttt{Leslie2Protocols} Lake library.


\section{Setting and method}


Three protocols occur in the case study.
Each is given as a list of properties over the calls and returns of its interface.
A property quantifies over \emph{correct} processes, that is, over processes that are never corrupted.

Asynchronous Byzantine Agreement (ABA).
Processes start with a bit in $\{0,1\}$ and may return a bit.
\begin{itemize}
  \item Validity: if a correct process returns $b$ then a correct process had
    $b$ as input.
  \item Agreement: if two correct processes return, then their outputs are
    equal.
  \item $\varepsilon$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\varepsilon$, all correct processes will eventually return.
\end{itemize}

Graded Binding Crusader Agreement (GBCA).
Processes start with a binary input in $\{0,1\}$ and may return a value in
\[
  \{(0,2),\ (0,1),\ (\bot,0),\ (1,1),\ (1,2)\}.
\]
\begin{itemize}
  \item Validity: if a correct process does not return $(b,2)$ then a correct
    process had $1-b$ as input.
  \item Graded Agreement: if two correct processes return $(b,X)$ and
    $(b',X')$ then $b = 0 \Rightarrow b' \neq 1$ and $X = 2 \Rightarrow X' \neq \bot$.
  \item Binding: when a correct process returns then a bound value $b$ is
    defined and, in all extensions of the execution, correct processes do not return $(1-b,1)$ or $(1-b,2)$.
  \item Termination: if $n-f$ correct processes take part in the protocol then
    all correct processes will eventually return.
\end{itemize}
In the second clause of Graded Agreement the symbol $\bot$ stands in the grade component, where the return domain admits only $2$, $1$ and $0$. It is read here as the grade $0$, the sole grade paired with the value $\bot$.
The encoding realises that reading: a grade-2 return and a grade-0 return of the same instance exclude one another.
The bound value of the Binding clause is realised by its complement: the specification carries the set of bits it can no longer hand out, and the clause's $1-b$ is a member of that set (D19).

Weak Common Coin (WCC).
Processes start with no input and may return a bit.
\begin{itemize}
  \item $\varepsilon$-Goodness: with probability $\varepsilon$, all correct
    processes return $0$ (resp.\ $1$).
  \item Unpredictability: until $f+1$ processes have called WCC, all outcomes
    are still possible.
  \item $(1-\failmass)$-sure Termination: if $n-f$ correct processes take part in
    the protocol then, with probability $1-\failmass$, all correct processes will eventually return.
\end{itemize}

What this development establishes is Validity and Agreement for ABA, machine-checked.
What it does not establish is the rest.
Termination, Unpredictability and fairness are out of scope.
The weak common coin is held at specification level rather than implemented: its own implementation over Gather and SRSD is not modelled here, so $\varepsilon$-Goodness enters as an assumption.

Every protocol $P$ with sub-protocols $Q$ is treated in two moves.
The first move is substitution: in a fixed context, each sub-implementation is replaced by the corresponding specification, which is sound by precongruence.
The second move is the core simulation: the core algorithm of $P$ composed with the specifications of its sub-protocols is simulated by the specification of $P$. Composing the inclusions places the implementation of $P$ inside the specification of $P$. The recursion stops at WCC, which is left at specification level.
GBCA is carried to implementation level twice, by two verified implementations of one specification.
The direct implementation calls no sub-protocol, so no further substitution arises there.
The gather-based implementation of Section~\ref{sec:aba-gather} continues the recursion: GBCA over two gather instances, gather over reliable broadcast, and reliable broadcast concrete.
The subject of the argument is the protocol: $n$ programs beside a network and a coin oracle, given in that form in Section~\ref{sec:aba-protocol} --- one automaton per process, carrying that process's round loop beside its round's record and a flag saying whether its own program has been replaced, and one automaton holding the message sets, the corrupted set and the corruption budget.
Substitution needs the sub-protocol it replaces to be a component, so the first step of the argument reads that system as a composition of components (Theorem~\ref{thm:aba-protocol-composed}).
That step is an inclusion, and it is where the chain passes from implementation to specification: the composed system carries the network state of every round, which no process holds, and a round instance answers at a process the protocol has terminated (D22).
The substitution then runs in those coordinates, and the hand-built core simulation runs in them too.

\paragraph{Object names.}
Transition System~1 is the ABA specification, Transition System~2 the GBCA specification, Transition System~3 the WCC specification, Transition System~4 the gather specification and Transition System~6 the BRB specification.
These names are used throughout this section and follow the numbering of the source blueprint~\cite{LeslieBP}, whose Transition Systems~5 and~7 (SRSD and AVSS) are not encoded; the source's pseudocode is numbered there as well: the source blueprint's Algorithm~1 is the ABA core algorithm, its Algorithm~2 the GBCA implementation, its Algorithm~4 the gather implementation over reliable broadcast (taken from~\cite{AFW25}) and its Algorithm~6 Bracha's reliable broadcast (taken from~\cite{Bra87}).
Of its Algorithms~1 and~2 only the ABA core is reproduced here; Algorithms~4 and~6 are both encoded, in Section~\ref{sec:aba-gather}.
The cited paper carries a third, independent numbering, always written here with ``ABDY22's'' attached: ABDY22's Algorithm~2 is the weak-coin agreement framework $AA_\varepsilon$, which the source blueprint's Algorithm~1 realises (ABDY22's Algorithm~1, the strong-coin framework over ungraded BCA, is not encoded in this development); ABDY22's Algorithm~6 is the graded sub-protocol.

A cross-reference of the form ``Algorithm~\ref{alg:aba-core}'' always points to a displayed float of this document, whose numbering runs independently of both; the other two numberings appear only in the phrases ``the source blueprint's Algorithm~$k$'' and ``ABDY22's Algorithm~$k$''.
A \emph{ghost output} is a value a specification holds as state and announces on a return label, which no program reads and on which no row's firing depends (D29).
There are two in this development, the round's bound bit and a gather instance's core, and both are called that below.
A \emph{state erasure} deletes a state component that no transition's firing depends on, and the \emph{ghost-free system} of a protocol is its implementation with the adversary's ghost record deleted.
The grades are $2$, $1$ and $0$ here and in~\cite{ABDY22} and~\cite{AFW25}, where Transition System~2 of the source blueprint writes $A$, $B$ and $C$.
Bracha's third message level is $\mathrm{VOTE}$ here and in the source blueprint, where both~\cite{ABDY22} and~\cite{AFW25} write $\mathrm{READY}$.
Its steps fire on the receipts and at the quorums of Algorithm~1 of~\cite{AFW25}, where Algorithm~6 of the source blueprint fires the echo step on an $\mathrm{INIT}$ receipt alone and puts $n-f$ at every quorum.
The naming difference carries no deviation label, and the rest is D34.


\paragraph{Outside the model.}
Two features of~\cite{LeslieBP} are deliberately not encoded.
The first is fairness: the source marks each transition fair or unfair, and a fair execution is one that is finite and ends in a fair deadlock or contains infinitely many fair transitions.
The second is partial information: the source carries adversaries given by a pair of observation functions on states and on labels, together with the belief construction that turns such an adversary into an omniscient one on a derived system.
Neither appears here.
Every adversary in this section is omniscient, so the observation functions are the identity and the belief construction is not needed.
The fairness markings bear only on liveness, which is out of scope.

\paragraph{Notation.}
Write $[n]$ for the identifier set and $F \subseteq [n]$ for the corrupted set.
The value domain of Transition System~3 is $\{0,1,\bot,\top,\dagger\}$, the type
\leandecl{PLTS.ABA.CoinValue}, where $\bot$ is unresolved, $\top$ is an adversarially
resolved outcome, and $\dagger$ is a resolution that delivers to no process (D17).

Every transition rule is displayed as a guard above a labelled step into an explicit distribution.
A Dirac target and a genuinely probabilistic one are therefore distinguishable in that display.
Exactly two transitions in the whole development are non-Dirac: the flip of Transition System~1 and the resolving call of Transition System~3.
Both follow the same distribution, displayed in Definition~\ref{def:aba-parameters}; the flip reads it through the map that drops the bit (D21).

    The adversary of~\cite{AFW25} chooses the corrupted set initially, so a payload sent to all stands on its sender's correctness, where under D1 a sender corrupted after its send may equivocate, and the certificate that holds the later returns to the core counts committed payloads, which stay fixed whatever happens to their sender.
  \item D33: both gathers of the round are the binding form, where the second call of Algorithm~4 of~\cite{AFW25} is non-binding.
    The round's counting reads the grade off a common core of the second gather, and Remark~22 of~\cite{AFW25} makes the core of a non-binding gather a prophecy variable in the sense of~\cite{AL91}, determined by the completed execution alone, which a forward simulation cannot write at the specification's rule, since the value chosen there must hold in every extension.
    The binding form makes it a history variable, determined by the prefix, and a binding gather is a non-binding gather with one phase more, so every execution of the round is an execution of Algorithm~4 of~\cite{AFW25}.
  \item D34: Bracha's rounds follow Algorithm~1 of~\cite{AFW25}, where Algorithm~6 of the source blueprint fires the echo step on an $\mathrm{INIT}$ receipt alone and puts $n-f$ at every quorum.
    The echo step fires on an $\mathrm{INIT}$ receipt from the leader, on $\mathrm{ECHO}\,m$ receipts from more than $(n+f)/2$ senders, or on $f{+}1$ $\mathrm{VOTE}\,m$ receipts, which are the three cases of the guard of \leandeclnamed{echo}{PLTS.ABA.BRB.BrachaStep.echo}.
    The vote step fires on that $\mathrm{ECHO}$ quorum or on $f{+}1$ $\mathrm{VOTE}\,m$ receipts, and the return takes $2f{+}1$ $\mathrm{VOTE}\,m$ receipts.
    The quorum is \leandecl{PLTS.ABA.Parameters.echoReceiptQuorum}, which is $(n+f)/2 + 1$, and the third message level is named $\mathrm{VOTE}$ here and in the source blueprint where both~\cite{ABDY22} and~\cite{AFW25} write $\mathrm{READY}$.
    The certificate the refinement carries is an $\mathrm{ECHO}$ receipt quorum at that size, and a correct echo of $m$ carries the leader's input unless the leader is corrupted.
  \item D35: the gather rows carry the order in which Algorithm~5 of~\cite{AFW25} sends, where Algorithm~4 of the source blueprint states each send as a rule firing on its receipts alone.
    The vote requires the sender's own $\mathrm{ECHO}$, the bind call requires the sender's own $\mathrm{VOTE}$ and no earlier bind call, and the return requires the returner's own bind call, which the write-once field $\mathit{sentBind}$ of the gather record holds.
    The $\mathrm{ECHO}$ payload is the set of entries the input broadcasts have returned to the sender, which is what Algorithm~5 of~\cite{AFW25} and Algorithm~4 of the source blueprint both send.
    The row fires once that set has $n-f$ entries, which is the source blueprint's guard.
  \item D36: the input-enabledness loop of the ABA interface is guarded on the record it stands beside, \leandeclnamed{inputLoop}{PLTS.ABA.Implementation.ProgramStep.inputLoop} absorbing a call at a process holding an input and the commit row carrying the label at a process holding none, and Transition System~1 splitting the label the same way, \leandeclnamed{callLoop}{PLTS.ABA.SpecStep.callLoop} looping at a filled record entry and \leandeclnamed{callSet}{PLTS.ABA.SpecStep.callSet} writing an empty one, where the source's loop is enabled at every state beside its recording rule, so that a first call may be dropped there and a later one recorded.
    The call label is enabled at every state in both systems, and every write to the ghost record is a first write, so the record holds each never-corrupted process's first genuine call.
    That call is the witness Validity names: \leandecl{PLTS.ABA.ValidityTrace} asks of every return of $b$ by a never-corrupted process an earlier $\mathrm{callABA}(id',b)$ at a never-corrupted $id'$, first among $id'$'s $\mathrm{callABA}$ labels in the trace.
\end{itemize}

\subsection{The ABA specification and its safety}

The three specification systems locate the adversary differently from the implementations they stand for.
An implementation puts processes that read only their own replacement flag beside an explicit network-adversary PLTS, which owns the corrupted set together with its budget and authorises every Byzantine action by the guard $k \in F$ of a component.
A specification carries no network component at all.
Its adversarial transitions are bare nondeterministic choices, resolved by the scheduler: the corruption rule of Transition System~1, its two corrupted interface rules (D23), the adversary-chosen returns under $\top$ at Transition System~3, and the disjunct $id \in F$ in the $F$-blind support counts of Transition Systems~1 and~2.
Leaving those choices unstructured is sound, because a specification constrains from above.
An unstructured adversary makes the specification more permissive, never less.
Trace-distribution inclusion requires that every behaviour of the implementation be matched by some resolution of the specification's nondeterminism, and the safety theorems quantify over all such resolutions.
A specification adversary with more freedom therefore weakens neither obligation.

\input{nodes/def-aba-spec}

The specification has four control states, keyed on the mode and on whether a value is decided: $mode = flipEnabled$ with $val = \bot$, $mode = decisionEnabled$, $mode = noRuleEnabled$, and $mode = flipEnabled$ with $val \neq \bot$.
Rule 3 (\leandeclnamed{coinFlip}{PLTS.ABA.SpecStep.coinFlip}) is the branch out of $flipEnabled$ at an undecided value, and it is the only probabilistic transition of the system.
Its three outcomes carry $\varepsilon$, $1-\varepsilon-\failmass$ and $\failmass$: the flip enables the decision, leaves the state unchanged, or fails to deliver (D17).
Rule 4 (\leandeclnamed{decide}{PLTS.ABA.SpecStep.decide}) is the sole writer of $val$, and it is the only $\tau$-rule that $decisionEnabled$ can enable.
Enabledness is wider than the control graph shows.
Rule 1 fires wherever $input[id] = \bot$ and rule 2 wherever $input[id] \neq \bot$; rule 6 fires wherever the identifier it names is uncorrupted and the budget has room, and rules 7 and 8 wherever the identifier it names is corrupted.
Rule 3 requires the mixedness guard beside $mode = flipEnabled$ and $val = \bot$: both bits must carry $f{+}1$ support, so an execution on which one bit is never supported never flips.
Rule 4 is enabled at every state with $val = \bot$, $mode \neq noRuleEnabled$ and some bit carrying $f{+}1$ support, hence at $flipEnabled$ as well as at $decisionEnabled$.
At a decided value the enabled rules are 1, 2, 5, 6, 7 and 8, and at $noRuleEnabled$ they are 1, 2, 6, 7 and 8; neither state enables a $\tau$-rule.
The guards on rule 4 are the entire constraint on the value decided (D13).

A flip that enables the decision cannot be discarded: at $decisionEnabled$ the decision is the only $\tau$-rule the mode can enable.
The undelivered branch of mass $\failmass$ (D17) is absorbing: $noRuleEnabled$ enables no $\tau$-rule.
The flip carries the mixedness guard, so the branch is reachable only from a state where both bits carry $f{+}1$ support.
Rules 1 and 2 are drawn on $flipEnabled$ alone.
Rule 1 is enabled at a process whose record entry is empty and rule 2 at a process whose entry is filled, so the call label is enabled in every state (D36).
Three of the eight rules are not drawn: rule 6 (\leandeclnamed{fail}{PLTS.ABA.SpecStep.fail}), the guarded corruption rule (D1), and rules 7 and 8 (\leandeclnamed{callByzantine}{PLTS.ABA.SpecStep.callByzantine} and \leandeclnamed{retByzantine}{PLTS.ABA.SpecStep.retByzantine}), the corrupted interface (D23), each enabled at a corrupted process in every state and none of them writing the mode.}

\noindent\textbf{Transition System 1: the ABA specification.}

\medskip \noindent\textbf{State.} The record \leandecl{PLTS.ABA.SpecState}.
\begin{itemize}
  \item $input : [n] \to \{0,1,\bot\}$, a ghost record of the genuine $\mathrm{callABA}$ events (D13).
  \item $ret : [n] \to \mathbb{B}$, which processes have returned.
  \item $F \subseteq [n]$, the corrupted set.
  \item $val : \{0,1,\bot\}$, the decision value; once it is a bit, every return carries it.
  \item $mode \in \{flipEnabled, decisionEnabled, noRuleEnabled\}$, the control mode, \leandecl{PLTS.ABA.ControlMode} (D21).
\end{itemize}
\noindent Here $\mathbb{B}$ is the two-element type, written $0,1$ for protocol bits and $\mathrm{false},\mathrm{true}$ for flags.
The record carries no per-process call row, no bound value and no coin field: the mode is what the three of them are replaced by (D21).
The source blueprint's $Initial$ clause mentions an undeclared $out$ field; the field is omitted.

\noindent\textbf{Labels.} $\mathrm{callABA}(id,b)$, $\mathrm{retABA}(id,b)$, $\mathrm{fail}(id)$ and $\tau$, for $id \in [n]$ and $b \in \mathbb{B}$.

\noindent\textbf{Input-enabled labels.} $\mathrm{callABA}(id,b)$, by rules~1 and~2 together, rule~1 at an empty record entry and rule~2 at a filled one (D36).
The label $\mathrm{fail}(id)$ is enabled where $id \notin F$ and $|F| < f$, the guards of rule~6 (D1).

\noindent\textbf{Initial.} $input = \bot^{[n]}$, $ret = \mathrm{false}^{[n]}$, $F = \emptyset$, $val = \bot$ and $mode = flipEnabled$, the superscript marking a constant map on $[n]$.

\medskip \noindent In each rule $id \in [n]$ and $b \in \mathbb{B}$ are parameters, and $s$ is the source state.
Write $InputSupport(s,b)$ for
\[ \bigl|\{ id \in [n] : input[id] = b \ \vee\ id \in F \}\bigr| \ \geq\ f + 1 , \]
the $f{+}1$ $F$-blind support of $b$ (D13, D15), \leandecl{PLTS.ABA.InputSupport}.

\medskip
\noindent\textbf{1.} \leandeclnamed{callSet}{PLTS.ABA.SpecStep.callSet} (D13, D36).
Guard $input[id] = \bot$.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;}
   \delta\bigl(s[\,input[id] := b\,]\bigr) \]
The write is a first write: the guard is the empty entry, so the record holds the bit of the process's first genuine call.

\noindent\textbf{2.} \leandeclnamed{callLoop}{PLTS.ABA.SpecStep.callLoop} (D13, D36).
Guard $input[id] \neq \bot$.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;} \delta(s) \]
The rule writes nothing.

\noindent\textbf{3.} \leandeclnamed{coinFlip}{PLTS.ABA.SpecStep.coinFlip} (D17, D21).
Guard $mode = flipEnabled$, $val = \bot$ and $InputSupport(s,b)$ for each of the two bits $b$, the mixedness guard.
\[ \begin{aligned}
     s \xrightarrow{\;\tau\;}\ \
     &\varepsilon\cdot\delta\bigl(s[\,mode := decisionEnabled\,]\bigr)
     + (1-\varepsilon-\failmass)\cdot\delta(s)\\
     &{}+ \failmass\cdot\delta\bigl(s[\,mode := noRuleEnabled\,]\bigr)
   \end{aligned} \]
The three masses are the image of the coin distribution of Definition~\ref{def:aba-parameters} under the map that drops the bit, \leandecl{PLTS.ABA.flipPMF}: one bit goes to $toDecisionEnabled$, the other bit and the adversarial outcome to $toFlipEnabled$, and $\dagger$ to $undelivered$.
No rule of the system reads a coin bit.

\noindent\textbf{4.} \leandeclnamed{decide}{PLTS.ABA.SpecStep.decide} (D13).
Guard $val = \bot$, $InputSupport(s,b)$ and $mode \neq noRuleEnabled$.
\[ s \xrightarrow{\;\tau\;}
   \delta\bigl(s[\,val := b,\ mode := flipEnabled\,]\bigr) \]

\noindent\textbf{5.} \leandeclnamed{ret}{PLTS.ABA.SpecStep.ret}.
Guard $val = b$ and $ret[id] = \mathrm{false}$.
\[ s \xrightarrow{\;\mathrm{retABA}(id,b)\;}
   \delta\bigl(s[\,ret[id] := \mathrm{true}\,]\bigr) \]

\noindent\textbf{6.} \leandeclnamed{fail}{PLTS.ABA.SpecStep.fail} (D1).
Guard $id \notin F$ and $|F| < f$.
\[ s \xrightarrow{\;\mathrm{fail}(id)\;}
   \delta\bigl(s[\,F := F \cup \{id\}\,]\bigr) \]
The guards are the condition under which the transform $\mathrm{corrupt}$ has an effect, so moving them onto the row leaves the effect unchanged and narrows the enabledness alone.

\noindent\textbf{7.} \leandeclnamed{callByzantine}{PLTS.ABA.SpecStep.callByzantine} (D23).
Guard $id \in F$.
\[ s \xrightarrow{\;\mathrm{callABA}(id,b)\;}
   \delta\bigl(s[\,input[id] := b'\,]\bigr),
   \qquad b' \in \mathbb{B} \text{ arbitrary} \]
The recorded bit is independent of the one the label declares: a corrupted caller's declared input need not be what is recorded.

\noindent\textbf{8.} \leandeclnamed{retByzantine}{PLTS.ABA.SpecStep.retByzantine} (D23).
Guard $id \in F$.
\[ s \xrightarrow{\;\mathrm{retABA}(id,b)\;} \delta(s) \]
A corrupted process returns any bit at any time and the state does not move.
Rule~5 stays available to it, so the two corrupted rules add behaviour and remove none.

\medskip
\noindent Two of the three guards on rule~4 are load-bearing for safety.
Without $val = \bot$ the specification violates Agreement: a second firing rewrites the decision value between two returns, and the two returns carry different bits.
With it, rule~4 being the sole writer of $val$, the decision value is write-once by the shape of the system and not by an invariant.
Without $InputSupport(s,b)$ the specification violates Validity.
Take $n = 4$, $f = 1$, the recorded inputs $1,0,0,0$ and the sole holder of $1$ corrupted.
A decision of $1$ there has every never-corrupted process inputting $0$, and the guard, demanding $f + 1 = 2$ recorded-or-corrupt supporters of $1$, is what rules that trace out.
The third guard, $mode \neq noRuleEnabled$, carries no safety weight.
It is the D17 outcome: an undelivered flip takes the decision away with every other $\tau$-rule.

\noindent The mixedness guard on rule~3 carries no safety weight either.
It is where the specification holds the liveness half of Validity.
A supported bit has a never-corrupted recorded inputter, by the budget pigeonhole \leandecl{PLTS.ABA.InputSupport.correct_supporter}, so under correct unanimity on one bit the other bit is supported by corrupted identifiers alone, at most $f$ of them, and the guard fails at every state such a run reaches.
The flip is then unreachable, and with it every probabilistic branch of the system, so the unanimous path is Dirac and rule~4 can write only the input.
The guard holds that structurally, in the guard rather than in a proof.

\noindent Rules~7 and~8 constrain nothing.
The bit a corrupted process returns is arbitrary and the state does not move, so no property of the system can constrain such a return; the trace predicates of Theorem~\ref{thm:aba-spec-safe} accordingly quantify over never-corrupted returners.
The write of rule~7 is the one place a recorded bit is replaced.
The support of the value decided survives it, by \leandecl{PLTS.ABA.InputSupport.callByzantine}: the writer $id$ lies in $F$, so the $F$ disjunct of $InputSupport$ counts it whichever bit it now records.

\dynamics{How a decision arises}{%
Which rule fires is scheduler nondeterminism, resolved by the adversary; the
flip is the only source of randomness.
The flip is enabled at $mode = flipEnabled$, with nothing decided, and with each of the
two bits carrying $f{+}1$ support.
One firing resolves into exactly one of three outcomes.
The outcome $toFlipEnabled$ leaves the state unchanged, so the flip is enabled again.
The outcome $toDecisionEnabled$ sets $mode := decisionEnabled$, and there the decision is the only $\tau$-rule
the mode can enable, the flip requiring $mode = flipEnabled$.
The decision is enabled whenever some bit carries $f{+}1$ support, and a state
that has passed the mixedness guard leaves some bit supported ever after.
The argument runs on the sum of the two support counts and not on either one,
since neither is monotone by itself: rule~1 may overwrite the record of an
uncorrupted identifier, which takes that identifier out of one of the two
supporter sets.
It puts it into the other in the same write, so the sum is unchanged; a write
into an empty entry raises the sum by one; a corruption puts its identifier into
both sets through the $F$ disjunct and raises the sum by one or two; rule~7
writes only at identifiers the $F$ disjunct already counts in both sets, so it
moves neither count.
The sum therefore never decreases.
At the flip it stands at $2f{+}2$ or above, hence at every later state one of
the two counts is $f{+}1$ or above and the decision is enabled at $decisionEnabled$.
A flip that enables the decision is therefore never wasted.
An undelivered flip sets $mode := noRuleEnabled$, which enables no $\tau$-rule at all (D17), so an
undelivered flip leaves the system with no decision and no return.

The three masses read as a liveness statement, which is stated here and not
proved in Lean.
Each firing enables the decision with probability $\varepsilon$ and fails to
deliver with probability $\failmass$.
An execution that keeps flipping therefore reaches $decisionEnabled$ or $noRuleEnabled$ almost surely, and under a
scheduler that fires nothing but the flip it reaches $decisionEnabled$ with
probability $\varepsilon/(\varepsilon+\failmass)$.
No safety argument uses either mass.
The reading is conditional on the guard: an execution on which one bit is never
supported never flips at all, and every state it reaches has a Dirac successor
distribution.
That is the unanimous case, and it is the liveness half of Validity: under
correct unanimity on $v$ the execution cannot flip, cannot enable the decision, cannot reach $noRuleEnabled$, and rule~4
can write only $v$.
The decision is \emph{enabled}, never forced, and the scheduler may decline it
forever, so the claim that the protocol decides with probability $1$ under fair
scheduling is a separate statement, not proved here.

The corrupted interface is arbitrary and influences nothing.
Rule~8 leaves the state fixed, and rule~7 writes only where the $F$ disjunct
already counts its identifier at both bits, so neither rule changes which bits
are supported, which mode the system is in, or what value rule~4 may write.
What they add is trace behaviour, which is why the properties are read at
never-corrupted returners.

The flip names no coin bit.
Reading the outcome $toDecisionEnabled$ as the coin agreeing with the round's reference value is an
outcome coupling carried by a refinement, not a component of Transition
System~1.
}

\noindent\textbf{The GBCA specification, round-$r$ instance.}

\medskip
\noindent\textbf{State.} The record \leandecl{PLTS.ABA.GBCA.SpecState}.
\begin{itemize}
  \item $call : [n] \to \{0,1,\bot\}$, the pending input of each process, $\bot$ when unset.
  \item $ret : [n] \to \mathbb{B}$, which processes have received their return.
  \item $excluded \subseteq \{0,1\}$, the exclusion set: the bits the instance can no longer hand out, written only by the internal binding transition (D19).
  \item $grade : \{0,1,\bot\}$, the grade lock, written $1$ by a grade-2 return and $0$ by a grade-0 return.
  \item $F \subseteq [n]$, the corrupted set, a local copy the $\mathrm{fail}$ broadcast keeps equal to the others.
\end{itemize}
\noindent Binding is internal specification state, it is negative information, and every return announces the surviving bit (D19, D29).
The set $excluded$ starts empty, and its only writer is the internal transition \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset}, which fires from $excluded = \emptyset$ alone and inserts one bit.
No rule ever revives a bit, so $excluded$ grows along every execution, the exclusion happens at most once per instance, and every reachable state has $excluded = \emptyset$ or $excluded = \{b\}$ for one bit $b$.
The grade-2 and grade-1 returns hand out a bit that is alive while the other bit is excluded; the grade-0 return hands out no bit.
All three take a bit $bnd$ under the guard $1-bnd \in excluded$ and announce it on the label.
That bit is a ghost output (D29): it is the bound value the specification holds, read off the exclusion set, and no program of any system below reads it.
The source blueprint's bound value embeds onto those reachable states, $bind = \bot$ as $excluded = \emptyset$ and $bind = b$ as $excluded = \{1-b\}$, so the two state shapes differ in the guards rather than in the cardinality (D19).

\noindent\textbf{Labels.}
$\mathrm{callG}(r,id,b)$, $\mathrm{retG}(r,id,out,bnd)$ with $out \in \{(b,2),\ (b,1),\ (\bot,0)\}$, $\mathrm{fail}(id)$ and $\tau$, for $id \in [n]$ and $b, bnd \in \mathbb{B}$.
The instance steps on these labels only; the family combinator supplies idle self-loops on every other label, the API labels of every round $r' \neq r$ among them.

\noindent\textbf{Input-enabled labels.}
$\mathrm{callG}(r,id,b)$, by the unconditional loop rule~2, and $\mathrm{fail}(id)$, whose rule~7 is total (D1).

\noindent\textbf{Initial.}
$call = \bot^{[n]}$, $ret = \mathrm{false}^{[n]}$, $excluded = \emptyset$, $grade = \bot$ and $F = \emptyset$.

\medskip
\noindent In each rule $id \in [n]$ and $b, v, bnd \in \mathbb{B}$ are parameters, and $s$ is the source state.

\medskip
\noindent\textbf{1.} \leandeclnamed{call}{PLTS.ABA.GBCA.Step.call}.
Guard $call[id] = \bot$.
\[ s \xrightarrow{\;\mathrm{callG}(r,id,b)\;} \delta\bigl(s[\,call[id] := b\,]\bigr) \]

\noindent\textbf{2.} \leandeclnamed{callLoop}{PLTS.ABA.GBCA.Step.callLoop}.
No guard.
\[ s \xrightarrow{\;\mathrm{callG}(r,id,b)\;} \delta(s) \]

\noindent\textbf{3.} \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset} (D14, D15, D19).
Guard
\[ \begin{aligned}
     &\bigl|\{id \in [n]\setminus F \mid call[id] \neq \bot\} \cup F\bigr| \ge n - f,\\
     &\bigl|\{id \in [n] \mid call[id] = 1-b \vee id \in F\}\bigr| \ge f + 1,\\
     &excluded = \emptyset.
   \end{aligned} \]
\[ s \xrightarrow{\;\tau\;} \delta\bigl(s[\,excluded := excluded \cup \{b\}\,]\bigr) \]
\noindent The support count is at the bit the rule \emph{spares}: excluding $b$ is certified --- witnessed by a \emph{receipt pattern}, an $F$-blind count on the delivered sets that is monotone along every execution --- by $f{+}1$ callers-or-corrupted of $1-b$.
The third guard admits the rule from the empty exclusion set only, so an instance excludes at most once and $excluded$ is a singleton ever after.

\noindent\textbf{4.} \leandeclnamed{retGrade1}{PLTS.ABA.GBCA.Step.retGrade1} (D14, D15, D19, D29).
Guard
\[ \begin{aligned}
     &v \notin excluded,\quad 1-v \in excluded,\quad 1-bnd \in excluded,\\
     &\bigl|\{id' \in [n] \mid call[id'] = 1-v \vee id' \in F\}\bigr| \ge f + 1,\\
     &ret[id] = \mathrm{false}.
   \end{aligned} \]
\[ s \xrightarrow{\;\mathrm{retG}(r,id,(v,1),bnd)\;}
   \delta\bigl(s[\,ret[id] := \mathrm{true}\,]\bigr) \]

\noindent\textbf{5.} \leandeclnamed{retGrade2}{PLTS.ABA.GBCA.Step.retGrade2} (D19, D29).
Guard $v \notin excluded$, $1-v \in excluded$, $1-bnd \in excluded$, $grade \in \{\bot, 1\}$ and $ret[id] = \mathrm{false}$.
\[ s \xrightarrow{\;\mathrm{retG}(r,id,(v,2),bnd)\;}
   \delta\bigl(s[\,grade := 1,\ ret[id] := \mathrm{true}\,]\bigr) \]

\noindent\textbf{6.} \leandeclnamed{retGrade0}{PLTS.ABA.GBCA.Step.retGrade0} (D14, D15, D19, D29).
Guard
\[ \begin{aligned}
     &1-bnd \in excluded,\\
     &\bigl|\{id' \in [n] \mid call[id'] = 1 \vee id' \in F\}\bigr| \ge f + 1,\\
     &\bigl|\{id' \in [n] \mid call[id'] = 0 \vee id' \in F\}\bigr| \ge f + 1,\\
     &grade \in \{\bot, 0\},\quad ret[id] = \mathrm{false}.
   \end{aligned} \]
\[ s \xrightarrow{\;\mathrm{retG}(r,id,(\bot,0),bnd)\;}
   \delta\bigl(s[\,grade := 0,\ ret[id] := \mathrm{true}\,]\bigr) \]

\noindent\textbf{7.} \leandeclnamed{fail}{PLTS.ABA.GBCA.Step.fail} (D1).
No guard.
\[ s \xrightarrow{\;\mathrm{fail}(id)\;}
   \begin{cases}
     \delta\bigl(s[\,F := F \cup \{id\}\,]\bigr)
       & \text{if } id \notin F \text{ and } |F| < f,\\
     \delta(s) & \text{otherwise.}
   \end{cases} \]

\medskip
\noindent Every transition of the instance is Dirac, so the instance is an LTS.

\dynamics{Binding as negative information}{%
An instance binds by removing an option rather than by choosing one.
The only writer of $excluded$ is \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset}, which inserts, and it fires
from the empty set only, so $excluded$ grows along every execution and one bit is
excluded per instance.
Corruption does not touch the field.
Every property below is a consequence of that monotonicity together with the
membership guards on the returns, with no auxiliary invariant.
Both value-bearing returns carry the same guard pair, $v \notin excluded$ and
$1-v \in excluded$: the bit handed out is alive and the other bit is already excluded.
That pair is Graded Agreement.
A return of $v$ puts $1-v$ into $excluded$; monotonicity carries that membership to
every later state of the execution; a later return of $w$ needs $w \notin excluded$, so
$w \neq 1-v$, so $w = v$.
Two returns of one execution therefore name the same bit whatever their grades,
and once any value-bearing return has fired a single bit is the only one any
extension can ever hand out.
The grade-0 return's guard $1-bnd \in excluded$ is the Binding clause read on this state:
$1-bnd$ is a bit that no correct process is handed at grade $\ge 1$
in any extension, because the value-bearing returns cannot hand out an excluded bit and
$excluded$ only grows.
A grade-0 return therefore commits the instance --- from that point at most one bit
is alive anywhere in the future --- which is what makes handing out no bit the
right answer, and it is why every return, grade-0 returns included, requires an exclusion
to have happened.
}

\dynamics{The bit on the label}{%
Every return rule takes a bit $bnd$ under the guard $1-bnd \in excluded$ and
announces it on $\mathrm{retG}(r,id,out,bnd)$ (D29).
On a reachable state $excluded$ holds at most one bit, so the guard determines
$bnd$ as the complement of the excluded bit, and all the returns of one round
announce one bit.
A value-bearing return of $v$ carries $1-v \in excluded$ as well, so it
announces $bnd = v$.
Here is what the announcement buys.
Binding is a claim about the extensions of an execution, and an inclusion of trace
distributions carries claims about labels; with the bit on the label the claim
reads on a single trace --- the round-$r$ returns of the trace name one bit, and
each of them that hands out a value hands out that bit --- and every step of a
refinement chain then transports it with no further argument.
The announcement adds no power to the scheduler.
The bit is a ghost output: no program reads it and no row's firing turns on it,
and a round that hands out no value ends with grade-0 returns alone which name
the surviving bit all the same.
}

\dynamics{Why the exclusion is once-only}{%
The guard $excluded = \emptyset$ on \leandeclnamed{bindUnset}{PLTS.ABA.GBCA.Step.bindUnset} is what keeps every round
completable.
Let us see what a second exclusion would cost.
Suppose the rule were enabled again after a grade-2 return of $v$, and fired on
$v$ itself.
The processes yet to return would then have no return available: the
value-bearing returns need a bit outside $excluded$, and there is none, while the grade-0 return
is blocked by the grade-2 guard.
The round would be stranded, and a fair scheduler could not complete it.
Under the once-only guard no such state is reachable.
A round that has answered one process at grade $\ge 1$ can answer every other
process the same way, since the surviving bit stays alive and the grade-2 guard
admits further grade-2 and grade-1 returns.
}

\dynamics{What the contract requires and what is proved here}{%
The GBCA contract listed at the start of this case study has four clauses.
The specification instance settles two of them outright and the safety half of
a third.
Graded Agreement is the guard pair on the value component and the grade guard
on the grade component, both structural (Theorem~\ref{thm:gbca-spec-binding}).
Binding is the grade-0 return guard read through monotonicity, again a theorem of
the same statement.
Validity has a safety half, that under unanimous correct input $v$ every return
of the instance hands out $v$ and no grade-0 return occurs, and that half is
Theorem~\ref{thm:gbca-spec-validity}.
What the clause requires beyond that half --- that the grade is the top one, and
that every correct process is answered at all --- is a statement about which
runs the scheduler must extend, as is Termination.
Fairness is not encoded here, so those clauses lie outside this development.
}

\dynamics{What the grades promise}{%
The grade records how much of the round its holder is committed to.
A grade-2 return commits to the surviving bit and is the grade that licenses a
decision.
A grade-1 return carries the surviving bit as the next estimate but records that
dissent was seen.
A grade-0 return carries no value, and its holder falls back on the coin.
The grade-2 and grade-0 guards are mutually exclusive: once a grade-2 return has
occurred no grade-0 return is enabled at that instance, and once a grade-0 return has
occurred no grade-2 return is.
The exclude, the dissenting bit at a grade-1 return and each of the two bits at a
grade-0 return are guarded by $f+1$ distinct supporters, counted $F$-blind, so the
count is monotone in $F$ and immune to later corruptions.
At most $f$ processes are ever corrupted, so any such set of $f+1$ contains a
member outside the final corrupted set, hence a never-corrupted genuine caller.
That member is the witness which carries Validity down to a caller: a bit $v$
handed out at grade $\ge 1$ requires $1-v \in excluded$, and the exclusion that put it
there certified $f+1$ $F$-blind supporters of $v$ itself.
}

\dynamics{The coin and its parameters}{%
One coin resolution has four outcomes.
With probability $\varepsilon$ the outcome is the bit $0$, and with probability
$\varepsilon$ it is the bit $1$.
In either case every correct process receives that bit.
With mass $1 - 2\varepsilon - \failmass$ the outcome is $\top$, the unresolved
coin: each process may then be handed either bit by the adversary,
independently of the others.
With probability $\failmass$ the outcome is $\dagger$, on which the resolution
delivers to no process at all (D17).
The outcome $\dagger$ models a delivery failure of the implementation this
specification stands for.
That implementation reconstructs the coin from an $\varepsilon$-correct
verifiable secret sharing, and the reconstruction can fail; on failure the coin
delivers nothing.
The two non-bit outcomes are distinct at the interface.
On $\top$ the coin delivers, and the adversary only picks which bit each
process receives.
On $\dagger$ no delivery occurs, and the callers of that instance hold no
return to read.
Transition System~3 is a specification, not an implementation.
The $\varepsilon$-Goodness it asserts is an assumption of this development, to
be discharged by an implementation over Gather and SRSD that is not modelled
here.
No result proved here reads the assumption: safety holds for every
admissible pair $\varepsilon, \failmass$, including $\varepsilon = 0$, where the
coin resolves to $\top$ or $\dagger$ almost surely.
Safety is insensitive to $\failmass$ for a further reason: the outcome $\dagger$
removes returns rather than adding any, and every safety property of this
development constrains the returns that do occur.
It is a termination argument that would consume the $\varepsilon$-mass, and
such an argument must carry the $\failmass$-mass too, since a $\dagger$ resolution
produces no return at all.
Termination and fairness are out of scope.
}


\section{The protocol}
\label{sec:aba-protocol}


What runs is $n$ programs, a network and a coin oracle.
Each program is one process: its round loop, the graded-agreement round record
of the round that loop is in, and the messages that have been delivered to it.
What it holds of corruption is one flag, saying whether its own program has been
replaced (D23).
No field of its record is a copy of the corrupted set, none is the corruption
budget, none names another process's status, and none records what the process
has multicast, so no guard of its rule table can ask whether another process is
correct or what this one has sent.
The network holds exactly what a process may not see: the message
sent sets of every sender, the DECIDED sets, and the corrupted set together with
the corruption budget.
It takes part in every send, in every delivery, and in every authorisation of
off-protocol behaviour.
It holds one record more, per round, which no program reads: the ghost record of
D30, written on every row by a parameter of the implementation and read out by a second
parameter that guards the two graded-agreement return rows.
That is where the bound bit a return announces comes from, and an implementation
supplies its content as it supplies the round message type, the round record and
the round's rows.
The coin oracle is the weak common coin, which this development holds at
specification level (Transition System~3).
The round loop and the graded-agreement round make up the programs, and this
section gives them in the form they run in: the automaton of one process, every
guard of which reads that process's own record, beside the adversary that holds
the rest.
Section~\ref{sec:aba-abdy} gives the same two again at ABDY22's implementation, as
pseudocode and then as rule inventories in which a guard is read against the
line of pseudocode it transcribes.
Each inventory enters the argument at a named point.
Each is one automaton read on the pair of components that hold its own state.
The graded-agreement inventory is read on the $n$ round records beside the
round's network state, which is the state one round instance runs on, and
that is how the refinement proved of it transports
(Theorem~\ref{thm:aba-gbca-instance-refines-specification}).
The round-loop inventory is read on the round-loop records beside the DECIDED
network, which is the state the core simulation's relation is defined on
(Theorem~\ref{thm:aba-hybrid-spec}).
In both cases the network is a component of the state and not a field of a record,
so a rule of the inventory and a rule of the composition are written against the
same object.

The ghost record is written by every row and read by the two graded-agreement return rows alone, so the one thing it can affect is the bit such a return announces.
That label belongs to the hidden alphabet of Definition~\ref{def:aba-labels}, and the outermost frame of the pipeline hides it, so the bit reaches no trace of the protocol.
Definition~\ref{def:aba-ghost-free} is the same system with the record deleted and the announcement left to the adversary, and Theorem~\ref{thm:aba-erasure} is the equality of achievable trace distributions between the two, from which every conclusion of either chain holds of the ghost-free system.


Algorithm~\ref{alg:gbca-impl} is the graded-agreement round of one process and
Algorithm~\ref{alg:aba-core} the round loop that calls it, with one
graded-agreement instance and one coin instance per round.
Instance identity is carried on the messages: in the cited paper every message
bears a tag $id$ naming the instance it belongs to, and the encoding carries
that tag as the round index $r$ on the round's labels, on the message sets
$sent(r,j)$ and on the round-tagged sub-protocol handshakes.


A process holds nothing of the corruption state.
No correct rule reads the corrupted set, and each Byzantine rule
reads only whether the process it belongs to is corrupted --- a question about
what the environment may do, not about the process's own data.
The program below therefore carries neither that set nor a bit standing in for
it, and the question is answered at the network, whose guard
$k \in F$ is the whole authorisation of an off-protocol step.

What the program does carry is the local effect of such a step.
A Byzantine call opens the process's round record exactly as a correct call would,
and a Byzantine return marks that record returned under the same receipt evidence.
The sub-protocol ports are input-enabled in that sense: a process can refuse
neither a call nor a return, and cannot tell an authorised one from a correct
one.
Only the choice of which handshake rows are available is the environment's.

The three components are composed by full synchronisation, communicating
through send, delivery and handshake-row labels that the composition hides.
The programs are composed by the product of Definition~\ref{def:synchronised-product},
taken over the extended alphabet of Definition~\ref{def:relabel} and read back
along the restriction that definition supplies.
The record of one automaton holds that process's own rows and nothing further,
so locality sits in the state shape and not in the guards alone.

None of this depends on how graded agreement is implemented.
The round loop, the DECIDED relay and its delivery, the coin handshake, the
corruption discipline, the adversary's table and the composition pipeline are
fixed by the round interface and the specification, and what an implementation
supplies is its round message type, its per-process per-round round record, its
round's rows and the content of the adversary's ghost record (D30).
Definition~\ref{def:aba-implementation} is written once, parametric in those four, and
instantiated here at the implementation of Algorithm~\ref{alg:gbca-impl};
Section~\ref{sec:aba-gather} instantiates it a second time.
The rendezvous alphabet is parametric in the message type, and is hidden before
it leaves the composition, so two instantiations need not agree
on it.

A system below the meeting point of the two chains therefore belongs to one
implementation or the other, and carries a superscript naming its source:
$\abdy{\mathrm{protocol}}(P)$ and $\abdy{\mathrm{composed}}(P)$ here, after the
authors of~\cite{ABDY22}, and $\afw{\mathrm{protocol}}(P)$ and
$\afw{\mathrm{composed}}(P)$ in Section~\ref{sec:aba-gather}, after those
of~\cite{AFW25}.
The systems the two chains share, $\mathrm{hybrid}(P)$ and $\mathrm{spec}(P)$,
carry none.

\begin{itemize}
  \item $\mathit{process} : [n] \to \mathrm{ProcessRecord}$ --- the local states, read
    off the round records.
  \item $\mathit{sent} : [n] \to \mathcal{P}(\mathrm{Message})$ --- the network state's
    sent sets: $\mathit{sent}(j)$ is the set of messages $j$ has multicast (D5).
  \item $\mathit{received} : [n] \times [n] \to \mathcal{P}(\mathrm{Message})$ ---
    $\mathit{received}(i,j)$ is the set of $j$'s messages the adversary has delivered to $i$, read off $i$'s own round record (D5).
  \item $F$ --- the network state's corrupted set, held equal to the other
    components' copies by the $\mathrm{fail}$ broadcast.
  \item $\mathit{bound} \in \{0,1,\bot\}$ --- the round's bound bit, $\bot$ before
    the round's first return, written by the three return rows and by nothing
    else (D29).
\end{itemize}
The bound bit is the one field of the state that is not the protocol's own data.
\leandecl{PLTS.ABA.GBCA.ByABDY.boundOf} computes it from $\mathit{sent}$, $F$ and the graded outcome: a value-bearing outcome gives the value it hands out, and an outcome carrying no value gives the payload of a correct $\langle\mathrm{VOTE}, b\rangle$ sender, $1$ where there is none.
A correct $\langle\mathrm{VOTE}, b\rangle$ sender holds an $n{-}f$ $\langle\mathrm{ECHO}, b\rangle$ receipt quorum and at most one bit carries such a quorum, so on a reachable state the two bit branches exclude one another.
A return of outcome $out$ announces $\mathit{bound}$ where the round has a bit on record and $\mathrm{boundOf}(\mathit{sent}, F, out)$ where it has none, and writes it back, so a round announces one bit on all of its returns.
No guard of the algorithm reads the field.
Multicasts are idempotent and thresholds count distinct senders, so message duplication and point-to-point scheduling are absorbed into the set model (D5).
Three derived quantities occur in the guards.
Set
\[
  \#_i(m) \;=\; |\{\, j \in [n] \;:\; m \in \mathit{received}(i,j) \,\}|,
  \qquad
  \mathit{Val}_i \;=\;
    \{\, b \in \{0,1\} \;:\; \#_i(\langle\mathrm{INPUT}, b\rangle) \ge n - f \,\},
\]
and write $\#_i(\mathrm{EC})$, $\#_i(\mathrm{VT})$, $\#_i(\mathrm{BD})$, $\#_i(\mathrm{SL})$ for the payload-blind counts, that is, the number of distinct senders from which $i$ holds some $\mathrm{ECHO}$, some $\mathrm{VOTE}$, some $\mathrm{BIND}$, some $\mathrm{ECHO5}$.
The set $\mathit{Val}_i$ is Algorithm~\ref{alg:gbca-impl}'s variable $\mathit{Valid}$, read off the delivered messages instead of being held as state, so the condition $|\mathit{Valid}| > 1$ becomes $\mathit{Val}_i = \{0,1\}$.
In the table $\mathrm{IN}\,b$, $\mathrm{EC}\,b$, $\mathrm{VT}\,v$, $\mathrm{BD}\,v$ and $\mathrm{SL}\,v$ abbreviate the five message forms, ``mcast'' abbreviates the insertion of a message into the sender's $\mathit{sent}$ set, and a dash marks an unguarded rule.
The two $\mathrm{ECHO5}$ rows and the ECHO5-reading guards of the three return rows are what D18 restores over the source blueprint's compressed four-round form, and carry no separate marker in the table.
Two further conditions of Algorithm~\ref{alg:gbca-impl}'s control flow are written into the same guards and are likewise unmarked: from the $\mathrm{BIND}$ level down each level requires the process's own send at the level below, and each return denies the cases above it.
The two $\mathrm{VOTE}$ rows ask for no own send, the $\mathrm{ECHO}$ they read being multicast by an \textbf{upon} handler and not in the body of the algorithm.

The blocks are taken in the order Algorithm~\ref{alg:gbca-impl} writes them.
A process reaches a block only after executing the send the block above it ends with, and that is the guard $\mathit{sentVote}_j$ set on the two $\mathrm{BIND}$ rules, $\mathit{sentBind}_j$ set on the two $\mathrm{ECHO5}$ rules, and $\mathit{sentEcho5}_i$ set on the three return rules.
The two $\mathrm{VOTE}$ rules carry no such guard.
What precedes the first \textbf{wait until} block is not a block a process must execute to the end but the \textbf{upon} handler that multicasts $\mathrm{ECHO}$, so a process may reach that block with its own $\mathrm{ECHO}$ still pending.
In each of the three return blocks the two rules are exclusive: the $\bot$ rule denies its block's case (a) at either bit, which is the \textbf{else} of that block's last line.
The three return rules are the three wait-until cases of the last block: case (a) is an $n{-}f$ $\mathrm{ECHO5}\,v$ quorum, case (b) an $n{-}f$ any-$\mathrm{ECHO5}$ quorum containing $\mathrm{ECHO5}\,v$ together with $f{+}1$ $\mathrm{BIND}\,v$ receipts and $|\mathit{Valid}| > 1$, and case (c) an $n{-}f$ $\mathrm{ECHO5}\,\bot$ quorum with $|\mathit{Valid}| > 1$.
That block ends in an \textbf{if}/\textbf{elif}/\textbf{else}, so each rule carries the denials of the cases above it beside the receipts its own case names: \leandeclnamed{retGrade1}{PLTS.ABA.GBCA.ByABDY.ImplementationStep.retGrade1} denies case (a) at either bit, and \leandeclnamed{retGrade0}{PLTS.ABA.GBCA.ByABDY.ImplementationStep.retGrade0} denies case (a) at either bit and case (b).
The denial of case (b) is carried in reduced form.
Case (b) requires at a bit $v$ four things: an $n{-}f$ any-$\mathrm{ECHO5}$ quorum, a received $\mathrm{ECHO5}\,v$, $f{+}1$ $\mathrm{BIND}\,v$ receipts and $|\mathit{Valid}| > 1$.
The first and the last are supplied by
\leandeclnamed{retGrade0}{PLTS.ABA.GBCA.ByABDY.ImplementationStep.retGrade0}'s own guard, an $n{-}f$
$\mathrm{ECHO5}\,\bot$ quorum being in particular an $n{-}f$ any-$\mathrm{ECHO5}$ quorum, so what is left to deny is the pair of the received $\mathrm{ECHO5}\,v$ and the $f{+}1$ $\mathrm{BIND}\,v$ receipts.
All three rules ask further that the returning process has been called, the D8 guard carried from the sends over to the returns.
Case (c) returns no bit.
The depth is what the grade-$1$ evidence buys (D18): $f{+}1$ $\mathrm{BIND}\,v$ receipts exceed the corruption budget, so they put a correct $\mathrm{BIND}\,v$ sender behind every grade-$1$ output, and that sender's own wait condition is an $n{-}f$ $\mathrm{VOTE}\,v$ quorum over the write-once $\mathrm{VOTE}$ level --- the object the binding argument of~\cite{ABDY22} counts.
The prose preceding Algorithm~6 in~\cite{ABDY22} says ``upon receiving $\mathrm{echo4}$ messages from $2t+1$ parties'' where its own pseudocode says $n - t$.
The two coincide only at $n = 3t+1$, and the encoding follows the pseudocode, $n - f$.
The $excluded$ and $grade$ fields of Transition System~2 are abstractions of these receipt patterns and belong to the specification alone; Theorem~\ref{thm:gbca-implementation-refines-specification} supplies them from the receipts.

The inventory above is one rule table, and the composition of Definition~\ref{def:aba-gbca-instance-by-abdy} is $n$ programs beside a network.
They are two presentations of the same round on the same state, and each rule of the table is a rule of the composition with its participants named.
A rule that touches both halves is a rendezvous:
\leandeclnamed{deliver}{PLTS.ABA.GBCA.ByABDY.ImplementationStep.deliver} reads the network state's sent set
in its guard and writes the receiver's row, so it splits into the two halves of a $\mathrm{gbcaDeliver}$ rendezvous, the network supplying the guard $m \in \mathit{sent}(j)$ and the receiver performing the row update.
No rule reads a second process, and Definitions~\ref{def:aba-programs} and~\ref{def:aba-network} are where each guard is written against one process record.

\dynamics{What is distributed and what is not}{%
Calling the encoding a distributed algorithm is a claim about which state a
rule is allowed to read, and the presentation states it in its sharpest form.
Every implemented part of the protocol is $n$ programs: the round loop, the
graded-agreement rows of each round, the DECIDED gossip and the receipt
bookkeeping of both sit inside $\mathrm{ABAProgram}(P,j)$, and every guard
of its forty-three rules is a function of $j$'s record.
Nothing of the protocol is shared.
The receipt rows and the control records each belong to one process, and every
quorum count is taken over one process's rows.
What a process holds of corruption is one bit of its own record, saying whether
its own program has been replaced (D23); the corrupted set, the budget and every
other process's status are outside its table.
Two components are not programs, and each is centralized for its own reason.
The first is the network.
It is not part of the protocol: it is the environment the protocol runs in, and
it holds what a process is not entitled to see --- who has multicast what, who
is corrupted, and how much corruption is left.
Putting the message sets there rather than in outboxes is what makes a
process's blindness to its own sends structural, and putting the corrupted set
there with its guard $k \notin F \wedge |F| < f$ makes the corruption budget a
component's guard rather than a condition on the executions the adversary
may produce.
The second is the coin oracle, and it is centralized of necessity.
An $\varepsilon$-common coin is a correlation between processes: the assumption
is that with probability at least $\varepsilon$ the processes of a round read the
same bit.
A correlation is not a property of any one process's state, so no assignment of
the oracle's transitions to per-process rules expresses it.
Writing the oracle as $n$ programs would mean supplying the protocol that
produces the correlation, which is the sub-protocol this development assumes
rather than proves.
It is also the one component whose transitions are not Dirac, and it occupies the
same coordinate in every system of the argument, from the protocol to the
composition the core simulation runs on.
}


\subsection{The composed system}

A sub-protocol may be replaced by its specification where it is a component of a composition, and nowhere else.
The protocol of Definitions~\ref{def:aba-programs} and~\ref{def:aba-protocol} does not present graded agreement as a component.
Each program runs the round loop and the graded-agreement rows of every round it has touched, and the single network holds the message sets of both.
This subsection reads the same protocol as a composition of components, and Theorem~\ref{thm:aba-protocol-composed} carries the protocol into it.
The first step is an inclusion, and the component boundary is where the chain passes from implementation to specification: below it is the system that runs, and above it everything is specification.
A composed state carries one graded-agreement instance per round at every moment, so the network state of every round survives there as specification state that no process holds, and a round instance, carrying no termination flag, answers a send or a delivery at a process the protocol has terminated (D22).
Graded agreement is a parallel component of the composed system, and that is what the substitution congruence consumes.

The cut is decided by one question: which network does a component own?
A round of graded agreement is a replaceable component exactly when the round's network belongs to that component --- the records its round messages sit in, the guard that lets one be delivered, and the injections a corrupted sender makes into it.
The instance of Definition~\ref{def:aba-gbca-instance-by-abdy} is drawn to own it.

Membership of $F$ is tested at the network alone: by the four Byzantine handshake rows, by $\mathrm{byzantineDecided}$, and by the Byzantine return row.
A round loop reads its own replacement flag and no more, so no rule of it names the corrupted set, the budget, or another process's status (D23).

The corruption rule \leandeclnamed{fail}{PLTS.ABA.Composition.ABANetworkStep.fail} is a synchronisation of every component of the composition, each keeping its own copy of $F$; at the process it names the round loop's half is \leandeclnamed{failSelf}{PLTS.ABA.Composition.RoundLoopStep.failSelf}, which writes the replacement flag, and at every other process it is \leandeclnamed{failIdle}{PLTS.ABA.Composition.RoundLoopStep.failIdle}, another process's corruption being no business of theirs.

\dynamics{The round loop}{%
Each process runs a five-phase cycle: idle, ready to call the round's GBCA,
awaiting its return, ready to call the round's coin, awaiting the coin.
The graded outcome fixes the next estimate, a grade-2 or grade-1 return of value $b$
setting it to $b$ and a grade-0 return clearing it to $\bot$; a cleared estimate is
filled by the coin of the same round, and a set estimate ignores that coin.
When the round's outcome was $(b,2)$, the step that receives the coin also
multicasts $\langle \mathrm{DECIDED}, b \rangle$ and advances the round.
A process holding $\langle \mathrm{DECIDED}, b \rangle$ from $f+1$ distinct
senders and not having multicast $\langle \mathrm{DECIDED}, b \rangle$ itself multicasts
$\langle \mathrm{DECIDED}, b \rangle$ itself, the $f+1$ threshold guaranteeing
one correct sender behind any echo.
The return rule requires $\langle \mathrm{DECIDED}, b \rangle$ from $n-f$
distinct senders together with the returning process's own prior multicast
of $b$.
The $n-f$ count is what excludes disagreement: two returns of different bits
would need two sender sets of that size, and any two such sets meet in more
than $f$ processes, hence in a correct one.
The own-multicast clause makes every return the endpoint of a diffusion its
own holder joined.
That a correct process never sends both payloads is not a property of the round
loop in isolation --- nothing in its rules forbids two grade-2 outcomes of opposite
bits in different rounds --- but of the composition, where Graded Agreement on
the GBCA family rules that pair out; the round loop alone guarantees only that
each process returns at most once, by the flag its return rule sets.
}

The round-loop inventory is read on a pair of components, as the one above is, and every guard in the table is read at one component: the counts of
\leandeclnamed{decidedSendRelay}{PLTS.ABA.Composition.RoundLoopStep.decidedSendRelay} and \leandeclnamed{ret}{PLTS.ABA.Composition.RoundLoopStep.ret} range over one receiver's own rows, and the
soundness guard $b \in decidedSent(j)$ that licenses a delivery is the network's, split from the freshness guard $b \notin decidedDelivered(i)$ and the write at the receiver.
Definitions~\ref{def:aba-programs} and~\ref{def:aba-network} write the same rules at the finer cut, where the round loop shares a record with the round records and the DECIDED sets share a component with the round's sent sets.

\dynamics{What the idealisation removes and what it leaves}{%
The substitution replaces one component, and the component is a round of graded
agreement together with that round's network.
Everything the network holds goes with it.
The round's sent sets disappear, and with them the guard $m \in sent(j)$ that made a
delivery sound, the write-once fields that recorded a multicast, and the
injection $\mathrm{byzantineGBCA}$ by which a corrupted sender put an arbitrary round
message into circulation.
The round specification has none of these: it has call entries, an exclusion set,
and graded returns.
What survives is everything the other three components hold.
The DECIDED sets keep their own delivery guard and their own Byzantine
injection, at the ABA network.
The corrupted set survives there too, with the budget $|F| < f$ as the guard on
the $\mathrm{fail}$ row, and so does the authorisation $k \in F$ of every
Byzantine handshake row --- including those of the graded-agreement,
whose effect is inside the replaced component and whose authorisation is not.
The asymmetry is decided by the cut and not by the argument: a Byzantine power
vanishes under an idealisation exactly when it is a power over the network the
idealised component owns.
This also fixes what it would take to vary the network's power.
A weaker network --- lossy delivery, a bound on injection, authenticated
channels of a different strength --- is a different system in the same position,
and it enters the chain by the same precongruence, with the round loops, the
DECIDED sets, the corrupted set and the coin oracle untouched.
The strength of the network is therefore a component that can be replaced, and
no proof outside that component depends on it.
}

\section{The gather-based implementation}
\label{sec:aba-gather}


Transition System~2 has a second verified implementation.
Attiya, Flam and Welch~\cite{AFW25} build graded agreement from two calls to a \emph{gather} sub-protocol and local counting, and the source blueprint carries the matching material: the gather specification (Transition System~4), a gather implementation over reliable broadcast (its Algorithm~4, the binding form of Algorithm~5 of~\cite{AFW25}, displayed as Algorithm~\ref{alg:gather-brb} below), and Bracha's reliable broadcast (Transition System~6 and its Algorithm~6, from~\cite{Bra87}, displayed as Algorithm~\ref{alg:brb}).
The two-gather core itself is displayed as Algorithm~\ref{alg:gbca-gather}.
This section carries the construction to implementation level in full, as a composition at every level: a round is $n$ graded-agreement programs beside the round's own network, in parallel with two gather instances, each $n$ programs beside the gather network in parallel with $2n$ Bracha instances carrying the inputs and the $\mathrm{BIND}$ payloads, each of those $n$ programs beside the instance's network.
The round interface $\mathrm{callG}/\mathrm{retG}$, Transition System~2 and every statement downstream of it are those of the sections above, so the two implementations differ only in the system at the bottom of the chain.

The verification is organised as substitutions inside the round.
Three tiers of the round are one composition with a different gather system in its two gather slots: the round over gather specifications, the same round over gather-over-broadcast instances, and the fully concrete round over gather-over-Bracha instances.
Three forward simulations connect them --- the broadcast substitution and the gather substitution, each an application of the congruences of Theorem~\ref{thm:forwardsim-congruence}, and the counting refinement into Transition System~2, proved on the composition through its row characterisation --- and compose to the round refinement.
At the protocol shape, each round speaks the extended alphabet itself, is gathered into the round-indexed family, and is put through the composed system's pipeline; the three substitutions become three stages whose last lands on $\mathrm{hybrid}(P)$, and from there the chain is the shared one.
Two systems are verified: the composed one, the gather-based counterpart of Definition~\ref{def:aba-composed}, and beneath it the implementation, the second instantiation of Definition~\ref{def:aba-implementation}, which is the gather-based protocol as it runs.

The two chains meet at $\mathrm{hybrid}(P)$ and are identical above it, and below it they run through systems of the same shape.

\end{algorithm}

\subsection{Reliable broadcast}


Reliable broadcast is the bottom tier, and its specification is the first point dynamic corruption shapes.
Under Transition System~6 a correct call fixes every return at the called value, and Algorithm~\ref{alg:brb} with the leader corrupted after its $\mathrm{INIT}$ leaves a window the specification forbids: until some correct process holds an $\mathrm{ECHO}$ quorum of more than $(n+f)/2$ senders, the injections of the now-corrupted leader can make the rounds deliver a different value.
The encoding therefore splits the recorded input from the committed value and guards the internal commit by $\mathit{ldr} \in F \vee input = m$ (D27): the corrupted leader's power is a commit of any value, the correct leader's value is fixed, and the window closes at the commit rather than at the call.
The refinement certifies the committed value by an $\mathrm{ECHO}$ receipt quorum of more than $(n+f)/2$ senders --- $F$-blind, monotone, unique by quorum intersection over the write-once echoes --- and fires the abstract commit on demand, as a two-step weak run under the first return.

\subsection{Gather}


Gather has every process broadcast a payload and returns to each caller a set of (process, payload) entries; the binding guarantee is that the returns share a committed core fixed no later than the first of them.
The specification holds that core as write-once state, of at least $n - f$ committed entries, and carries it on every return label, which is the label the source carries its bound identifier set on.
The core is a ghost output (D29): no process holds it, and a system built over the instance binds by reading its labels.
Remark~22 of~\cite{AFW25} determines the core of a non-binding gather only in hindsight; here it is an auxiliary variable in the sense of~\cite{AL91}, and the size bound the rule writing it requires is provable from the prefix of an execution.
Let us see why.
Write $w$ for the network state of the implementation, that is, the per-sender sent sets beside the corrupted set.
A correct sender's $\mathrm{VOTE}$ payload lies above an $\mathrm{ECHO}$ payload of each of $n - f$ senders, its own wait condition, so for every $q \notin F$ at least $n - f$ senders are dominated by $q$ in the sense that every $\mathrm{VOTE}$ of $q$ lies above one of their $\mathrm{ECHO}$ payloads.
Summing that bound over the rows outside $F$ and exchanging the order of summation gives a sender $j_0 \notin F$ dominated by at least $n - f - |F|$ of those rows, and $n - f - |F| \ge f + 1$ at $3f < n$.
The core is $j_0$'s $\mathrm{ECHO}$ payload, and its $n - f$ entries are $j_0$'s own wait condition.
Every correct committed $\mathrm{BIND}$ payload contains it: the payload is backed by an $n - f$ $\mathrm{VOTE}$ quorum, which meets the $f{+}1$ dominating rows in a process whose write-once $\mathrm{VOTE}$ payload lies above the core and below the payload.
The certificate that holds the returns after the first to the core that first return writes is the count of coordinates holding a committed $\mathrm{BIND}$ payload above it, which reaches $f + 1$ at the first return and is blind to $F$ and monotone.
Sending the $\mathrm{BIND}$ payload by reliable broadcast rather than on the network is what makes ``committed'' mean anything under dynamic corruption: a broadcast value is write-once whatever later happens to its sender, where a network multicast from a sender corrupted later fixes nothing.
The commit split of D26 is the per-entry form of the same reading.

The implementation is a composition: $n$ gather programs beside the gather network, which holds the core, in parallel with $2n$ reliable-broadcast instances read along pullbacks naming them, the instance's own events hidden.
A program keeps its own record of what the broadcast instances have returned to it, written on the return events, and its guards read that record and nothing of any other component.
The implementation is verified in two substitutions.
The gather-over-broadcast tier places the $2n$ broadcast specifications in the broadcast slots and is carried to Transition System~4 by the core refinement, whose returns are answered by one weak run --- the abstract commits, the write of the core where the specification holds none, the return --- with the core read off the gather network's own state.
The fully concrete tier places a Bracha instance in each slot and is carried to the previous one by congruence, the broadcast refinement lifted along the pullback naming each instance and through the operators the instance is built from.

\subsection{The two-gather round}


The round is Algorithm~\ref{alg:gbca-gather} as a composition: $n$ programs beside the round's own network, which carries no messages and holds the round's bound bit, in parallel with the two gathers read along pullbacks naming them.
The call is the first gather's call; the first gather's return to a process, which records the candidate, and that process's call of the second gather are two events; and so are the second gather's return, which records the grade off its counts, and the round's graded return (D24).
Both gathers are the binding form (D33).
The refinement into Transition System~2 is counting on the two cores, each written once.
A returned map carrying a value on all but $f$ entries makes the core the return carries do the same; a core carrying one value on at least $|S| - f$ entries leaves every other value at most $f$ entries on it, its $\ge n - f \ge 2f + 1$ entries admitting one value on all but $2f$, which is at once the uniqueness of the grade-1 bit and the grade-2 / grade-0 exclusivity of the grade guard.
The round's bound bit is the bit the first core carries on at least $|S| - f$ entries, written by the round's own network at the first gather's first return and announced by every graded return (D29).
The exclusion certificate --- the first core carrying the excluded bit on fewer than $|S| - f$ entries --- stands from the moment the core is written, so the specification's monotone $excluded$ is certified with no relay machinery, and the exclusion-on-demand discipline of the direct implementation's refinement carries over unchanged: a return needing an exclusion the specification does not yet hold is answered by the run $\mathrm{bindUnset}; \mathrm{ret}$, whose excluded bit is the complement of the bit the return announces.

\section{The gather-based chain}


Beneath the composed system is the protocol that runs.
It is Definition~\ref{def:aba-implementation} a second time, at the gather-based implementation: the same round loop, the same DECIDED sets, the same coin handshake, the same corruption discipline and the same pipeline, over a graded-agreement component that is the two gather instances and the $4n$ Bracha instances beneath them.
Three things separate that component from the composed system's, and all three are forced by what the implementation is.
A round of the composed system carries $4n+2$ networks, one per sub-protocol instance, while the adversary of the implementation carries one sent-set family per round; a round message therefore carries a tag naming the network it belongs to, and for a broadcast message the instance, whose index is its leader.
The sender index stays the sender, so a threshold still counts distinct senders (D5).
And the composed system indexes the local states by instance and then by process, while a program must hold its own data and no one else's; the round record is therefore transposed, holding one process's local state in every instance.
And a program of the implementation takes one row per thing it does, so the graded-agreement call broadcasts the input, the $\mathrm{BIND}$ send is a broadcast call, and the first gather's return to a process is that process's call of the second gather (D28), where the composed round takes two events for each; the implementation has no broadcast return either, a gather guard reading a $2f{+}1$ $\mathrm{VOTE}$ receipt quorum on the process's own local state in the instance where a composed program reads what the instance returned.
None of the three loses anything, because every guard of the gather-based implementation reads the acting process's own local states and the networks, and the two rows that read a network --- the adversary's delivery and its Byzantine injection --- belong to the adversary in either system.
Assembling the composed state from the implementation's undoes all three: the local states are transposed back, each network's sent set is projected out of the tagged sent-set family, and what each instance returned to a program is read off its own local states in the broadcast instances as the values with a vote quorum there.
That assembly is the simulation relation of Theorem~\ref{thm:aba-afw-protocol-composed}, which is a function rather than a correspondence --- the composed state is computed from the implementation's --- and the proof obligation of a row is which of the six projections takes the message it sends; a fused row is answered by a run of two events of the composed round, through a named intermediate state.
The relation carries the broadcast invariant at every instance of the view, which identifies a returned value with the value a guard of the implementation names: two vote quorums at one process name one value.
The adversary's ghost record is the third thing this instantiation supplies (D30): for each round, the two gathers' cores beside the round's bound bit, each written once.
The return-then-call row's broadcast of the candidate writes the first core, read off the projection of the tagged sent sets onto the first gather, and the bound bit as the bit that core carries on at least $|S| - f$ entries; a graded return writes the second core the same way and fires only with the bit its label carries equal to the one on record.
The composed round holds those three in its network components, which no program reads, so the relation reads them off the ghost record and a row's ghost write is the round's write of them.
One clause of the relation is not read off the implementation's state: a process whose round-$r$ second-gather local state carries an input has passed the round's return-then-call row, so the round's bound bit is on record, and that is what the announced bit of a graded return rests on.
