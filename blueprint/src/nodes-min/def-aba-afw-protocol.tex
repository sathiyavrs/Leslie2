\begin{definition}[The gather-based protocol]
  \label{def:aba-afw-protocol}
  \lean{PLTS.ABA.AFW.Message}\lean{PLTS.ABA.AFW.RoundEvent}\lean{PLTS.ABA.AFW.RoundVariables}\lean{PLTS.ABA.AFW.RoundStep}\lean{PLTS.ABA.AFW.Ghost}\lean{PLTS.ABA.AFW.firstGatherOf}\lean{PLTS.ABA.AFW.secondGatherOf}\lean{PLTS.ABA.AFW.ghostStep}\lean{PLTS.ABA.AFW.ghostBound}\lean{PLTS.ABA.AFW.protocolExtended}\lean{PLTS.ABA.AFW.protocolHidden}\lean{PLTS.ABA.AFW.protocol}\leanok
  \uses{def:aba-implementation, def:aba-round-over-bracha, def:aba-gather-over-bracha, def:aba-gather-core}
  Definition~\ref{def:aba-implementation} at the gather-based implementation: one tagged message type collapsing a round's $2n+2$ network states into one sent-set family, process-major round variables holding each process's local state in every instance, and twenty-six transitions of the round --- the round's own calls and returns with the call's loop, the two gather instances, the $2n$ Bracha instances beneath them, and the delivery with its loop at a terminated program: \leandecl{PLTS.ABA.AFW.protocol}.
  The network's ghost for a round is \leandecl{PLTS.ABA.AFW.Ghost}, the two gathers' cores and the round's bound bit, each written once: the first gather's return writes the first core, the second gather's return the second, and the round's first return the bit, $\mathrm{boundOfCore}$ of the first core, which \leandecl{PLTS.ABA.AFW.ghostBound} reads for the network's announcement (D29, D30).
\end{definition}
