\begin{definition}[The gather-based protocol]
  \label{def:aba-afw-protocol}
  \lean{PLTS.ABA.AFW.Msg}\lean{PLTS.ABA.AFW.StageRec}\lean{PLTS.ABA.AFW.StageStep}\lean{PLTS.ABA.AFW.gCallPayload}\lean{PLTS.ABA.AFW.Ghost}\lean{PLTS.ABA.AFW.ga1Of}\lean{PLTS.ABA.AFW.ga2Of}\lean{PLTS.ABA.AFW.ghostStep}\lean{PLTS.ABA.AFW.ghostOut}\lean{PLTS.ABA.AFW.protocolPre}\lean{PLTS.ABA.AFW.protocolGroup}\lean{PLTS.ABA.AFW.protocol}\leanok
  \uses{def:aba-flat-reading, def:aba-gbca-gather-low, def:aba-gather-low, def:aba-gather-core}
  The flat reading of Definition~\ref{def:aba-flat-reading} at the gather-based implementation, supplying the four things it asks for.
  The message type is tagged: a round of that implementation carries $4n+2$ message states --- one for each gather instance and one for each of the $4n$ Bracha instances --- and the tag names the message state a message belongs to, and for a Bracha message the instance, whose index is its leader.
  The adversary then holds one sent-set family per round, the sender index staying the sender, so a threshold still counts distinct senders (D5).
  The stage record is process-major.
  The composed reading indexes the local states by instance and then by process, and a program must hold its own data and no one else's, so $\mathrm{StageRec}$ holds process $j$'s local state in each gather instance and its local state in each of the $n$ instances of each broadcast family.
  Every guard of the gather-based implementation reads the acting process's own local states and the message states, and the two rows that read a message state --- the adversary's delivery and its Byzantine injection --- belong to the adversary, so the rearrangement loses nothing.
  The rows are those of $\mathrm{Gather.LowStep}$ and $\mathrm{GBCA.LowPairStep}$ cut into their process half and their network half: a send writes the sender's own record and the network records the message, and a delivery files the message in the receiver's own local state, dispatched on the tag.
  Three rows are fused, as they are in the composed reading (D28): the graded-agreement call broadcasts the input, the $\mathrm{BIND}$ send is a broadcast call, and the first gather's return to a process is that process's call of the second gather.
  The broadcast return is not a row: gather reads a broadcast delivery as an $n-f$ $\mathrm{VOTE}$ receipt quorum, never through a returned flag, and the composed reading embeds only the silent rows of a Bracha instance.
  The ghost record of a round is $\mathrm{Ghost}(n)$, the first gather's frozen core, the second gather's frozen core and the round's bound bit, each written once (D29, D30).
  $\mathrm{ghostStep}$ writes it.
  The link's broadcast of the candidate --- the stage multicast of an initial input-broadcast message of the second gather, which no other row carries --- freezes the first core at $\mathrm{coreOf}$ of the round's first gather message state and the bound bit at $\mathrm{boundOfCore}$ of that core; a graded return freezes the second core the same way; every other label leaves the record where it stands.
  The message state $\mathrm{coreOf}$ is read on is $\mathrm{ga1Of}$, the first gather's slice of the adversary's tagged sent sets beside its corrupted set, and $\mathrm{ga2Of}$ is the second's.
  $\mathrm{coreOf}$ reads the sent sets and the corrupted set alone, which is what lets the adversary compute a core from its own state.
  $\mathrm{ghostOut}$ reads the bit back, and the two graded-agreement return rows fire only with the bit their label carries equal to it.
  It is total: where the record holds no bit it computes one from the first gather's core, and on a reachable state the returner's own link has already written the bit.
  The adversary needs no new rows at all --- recording a multicast, checking a delivery and authorising a handshake row are already independent of the payload.
  Full construction: \leandecl{PLTS.ABA.AFW.protocol}.
\end{definition}
