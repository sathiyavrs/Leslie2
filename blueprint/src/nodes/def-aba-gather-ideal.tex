\begin{definition}[The gather implementation over broadcast specifications]
  \label{def:aba-gather-ideal}
  \lean{PLTS.ABA.Gather.GaMsg}\lean{PLTS.ABA.Gather.PRec}\lean{PLTS.ABA.Gather.IdealState}\lean{PLTS.ABA.Gather.IdealStep}\lean{PLTS.ABA.Gather.idealInst}\leanok
  \uses{def:aba-gather-spec, def:aba-brb-spec, def:aba-msgstate}
  Algorithm~4 of~\cite{LeslieBP}, which is the binding form of Algorithm~5 of~\cite{AFW25}, with each reliable broadcast held at specification level.
  The state is a two-part gather instance of Definition~\ref{def:aba-msgstate} beside $2n$ broadcast-specification states: $\mathit{brbIn}(k)$, the instance in which $p_k$ broadcasts its input, and $\mathit{brbBind}(k)$, the instance in which $p_k$ broadcasts its $\mathrm{BIND}$ payload (D32).
  An entry set $A$ is \emph{approved} when every entry $(k, x) \in A$ has $\mathit{brbIn}(k).val = x$: approval is commitment of every entry, read off the broadcast coordinates rather than signalled by an event (D28).
  The gather message state carries $\langle\mathrm{ECHO}, A\rangle$ and $\langle\mathrm{VOTE}, A\rangle$ with entry-set payloads; the $\mathrm{BIND}$ payload is sent through $\mathit{brbBind}$ and not on the message state.
  The rows: the environment call records the input and contributes it through $\mathit{brbIn}$ in the same step; the commit rows of the $2n$ broadcast coordinates are embedded as $\tau$-rules; delivery and Byzantine injection act on the message state (D5, D1); a process holding $n{-}f$ approved committed entries multicasts them as its write-once $\mathrm{ECHO}$; on $n{-}f$ senders' approved $\mathrm{ECHO}$ payloads below an approved set $U$ it multicasts $U$ as its write-once $\mathrm{VOTE}$; on $n{-}f$ senders' approved $\mathrm{VOTE}$ payloads below an approved $U$ it contributes $U$ through $\mathit{brbBind}$; and the return of $g$ requires $n{-}f$ coordinates $q$ with $\mathit{brbBind}(q).val = U_q \sqsubseteq g$ together with $g \subseteq \mathit{brbIn}(\cdot).val$.
  Corruption is one broadcast across the message state and all $2n$ coordinates (D1).
  The state carries one field more, the instance's core, and the return row writes it: a return reads the core already on record, and where there is none it writes $\mathrm{coreOf}$ of the message state and announces that.
  The field is auxiliary state (D29): no process holds it, no guard consults it, and every return label carries it.
  Full construction: \leandecl{PLTS.ABA.Gather.idealInst}.
\end{definition}
