\begin{definition}[The gather implementation over broadcast specifications]
  \label{def:aba-gather-over-broadcast-specification}
  \lean{PLTS.ABA.Gather.Message}\lean{PLTS.ABA.Gather.BaseProcessRecord}\lean{PLTS.ABA.Gather.StateOverBroadcastSpecification}\lean{PLTS.ABA.Gather.AlgorithmOverBroadcastSpecification}\lean{PLTS.ABA.Gather.instanceOverBroadcastSpecification}\lean{PLTS.ABA.Gather.instanceOverBroadcastSpecification_step_iff_algorithm}\leanok
  \uses{def:aba-gather-composition, def:aba-gather-spec, def:aba-brb-spec, def:aba-networkstate}
  The gather instance of Definition~\ref{def:aba-gather-composition} whose broadcast tier is $2n$ broadcast specifications, \leandecl{PLTS.ABA.Gather.instanceOverBroadcastSpecification}, and the algorithm that lists its transitions at the specification's labels, \leandecl{PLTS.ABA.Gather.AlgorithmOverBroadcastSpecification}, a relation on the composition's state.
  The state is the gather programs and the gather network beside $2n$ broadcast-specification states: $\mathit{inputBroadcasts}(k)$, the instance in which $p_k$ broadcasts its input, and $\mathit{bindBroadcasts}(k)$, the instance in which $p_k$ broadcasts its $\mathrm{BIND}$ payload (D32).
  The transitions are Algorithm~4 of~\cite{LeslieBP}, which is the binding form of Algorithm~5 of~\cite{AFW25}, with each reliable broadcast held at specification level.
  An entry set $A$ is \emph{approved at $j$} when $j$'s input broadcasts have returned every entry $(k, x) \in A$, which is that instance's return to $j$ and hence its commitment of $x$.
  The gather network carries $\langle\mathrm{ECHO}, A\rangle$ and $\langle\mathrm{VOTE}, A\rangle$ with entry-set payloads; the $\mathrm{BIND}$ payload is sent through $\mathit{bindBroadcasts}$ and is not a message of that network.
  The transitions: the environment call records the input at the gather program, and the process then calls its own input instance with the payload on that record; the commits of the $2n$ broadcast coordinates are silent transitions; delivery and Byzantine injection act on the gather network (D5, D1); a process whose input broadcasts have returned $n{-}f$ entries multicasts those entries as its write-once $\mathrm{ECHO}$; on $n{-}f$ senders' approved $\mathrm{ECHO}$ payloads below an approved set $U$ it multicasts $U$ as its write-once $\mathrm{VOTE}$; on $n{-}f$ senders' approved $\mathrm{VOTE}$ payloads below an approved $U$ it calls its bind instance with $U$; and the return of $g$ requires $n{-}f$ coordinates $q$ whose bind broadcast has returned $U_q \sqsubseteq g$ to the returner, together with $g$ below what the returner's input broadcasts returned.
  Each of those three transitions after the $\mathrm{ECHO}$ also requires the acting process's own send at the level below: the $\mathrm{VOTE}$ its own $\mathrm{ECHO}$, the bind call its own $\mathrm{VOTE}$ and no earlier bind call, and the return its own bind call, which the write-once field $\mathit{sentBind}$ of the record holds (D35).
  The call of an instance has two transitions rather than one.
  A broadcast specification answers a call on either of its own two call transitions, so the instance records the payload or remains unchanged; that split reaches the call of an input instance and the call of a bind instance alike.
  Corruption is one broadcast across the gather network and all $2n$ coordinates, and each coordinate's corrupted set stays equal to the gather network's (D1).
  The gather network's return transition writes the core where none is on record, as $\mathrm{coreOfNetwork}$ of its own network state, and carries it on the return label; the field is auxiliary state (D29), read by no program and consulted by no guard.
  \leandecl{PLTS.ABA.Gather.instanceOverBroadcastSpecification_step_iff_algorithm} is the characterisation by the algorithm: at a specification label, the transitions of the composition over the labels the projection sends there are exactly the cases of the algorithm at that label, on the same state and with the same distribution.
\end{definition}
