\begin{definition}[The ghost-free system]
  \label{def:aba-ghost-free}
  \lean{PLTS.ABA.Implementation.systemGhostFree}\lean{PLTS.ABA.ABDY.ghostFreeProtocol}\lean{PLTS.ABA.AFW.ghostFreeProtocol}\leanok
  \uses{def:aba-implementation, def:aba-protocol, def:aba-afw-protocol}
  The implementation of Definition~\ref{def:aba-implementation} at a one-element ghost record.
  The programs, the network rows, the coin oracle and the composition pipeline are those of that definition; what the instantiation settles is the adversary's record and the guard of the two graded-agreement return rows.
  The record of a round is the one element, so the update of D30 writes nothing that can be read back.
  The output of D30 is the full relation, so a graded-agreement return fires at either value of the bound bit its label carries, and the bit a return announces is the adversary's own choice.
  Full construction: \leandecl{PLTS.ABA.Implementation.systemGhostFree}.

  The two protocols have ghost-free readings at their own round message type, round record and round's rows: \leandecl{PLTS.ABA.ABDY.ghostFreeProtocol} against Definition~\ref{def:aba-protocol}, and \leandecl{PLTS.ABA.AFW.ghostFreeProtocol} against Definition~\ref{def:aba-afw-protocol}.
  Each is the protocol it is named for with the adversary's record dropped and nothing else changed, so each has the same alphabet as the protocol and sits in the same composition.
  The output of D30 is a relation, and that is what puts the three readings in one rule table.
  ABDY22's implementation instantiates it as the equation between the announced bit and $\mathrm{abdyGhostOutput}$ of the round, the gather-based implementation as the equation between the announced bit and the bit its own record holds, and the ghost-free system as the relation that holds of every bit.
\end{definition}
